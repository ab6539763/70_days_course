### 10:45 - 12:00 | LoRA 原理

```
原始权重 W → W + ΔW = W + BA
B: d×r  A: r×k  (r << d, r通常为8-64)
只训练 A 和 B，原始 W 冻结
```


### 9:45 - 10:30 | 模块二：LoRA 原理深度

#### 2.1 数学原理

LoRA（Low-Rank Adaptation）基于一个重要假设：模型微调时的权重变化是低秩的。

```
原始: W ∈ R^(d×k)
微调: W' = W + ΔW
LoRA: ΔW = B × A, 其中 B ∈ R^(d×r), A ∈ R^(r×k), r << min(d,k)

前向传播: h = W·x + ΔW·x = W·x + B·A·x
训练参数: 仅 A 和 B（原始 W 冻结）
```

#### 2.2 超参数选择

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| lora_rank (r) | 8-64 | 越大越强但越慢 |
| lora_alpha | 16-32 | 缩放因子，通常=2×rank |
| target_modules | q_proj,v_proj | 注意力层 |
| lora_dropout | 0.05-0.1 | 防过拟合 |
| learning_rate | 1e-4 ~ 5e-5 | 比全参数大10倍 |

#### 2.3 QLoRA：量化 + LoRA

```python
# QLoRA 在 4-bit 量化模型上做 LoRA
# 显存需求降低 75%，效果损失 < 1%

# LLaMA-Factory 配置
quantization_bit: 4
double_quantization: true
quant_type: nf4
```

### 10:45 - 12:00 | 模块三：微调 vs 其他方案决策

```
决策树：
  需要改知识？ → RAG（Day 25-38）
  需要改行为/风格？ → 微调
    数据量 < 100？ → Prompt 工程
    数据量 100-10000？ → LoRA
    数据量 > 10000？ → 全参数微调
  需要改能力？ → 预训练（超出本课程范围）
```

### 概念 1：与前面课程的关联

### 概念 2：工程实践要点

| 实践 | 具体做法 |
|------|----------|
| 版本控制 | 每天 Git 提交，写清楚 commit message |
| 环境隔离 | 使用 venv 或 conda，requirements.txt 锁定版本 |
| 错误处理 | try/except 包裹 API 调用，提供友好错误信息 |
| 日志记录 | 使用 logging 模块，记录关键操作 |
| 配置管理 | API Key 用 .env 文件，不提交到 Git |

### 概念 3：常见陷阱

1. **API Key 泄露**：绝不要将 Key 写入代码或提交到 GitHub
2. **无限循环**：Agent 必须设置 max_iterations
3. **上下文溢出**：注意 Token 限制，及时截断历史
4. **依赖冲突**：新安装包前检查 requirements.txt
5. **忽略测试**：每个功能都要有测试用例验证
