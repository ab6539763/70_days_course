### 延伸题 1:/stats 指令(F6 的深化)

给助手新增 `/stats`:显示本会话的——总轮数、用户/AI 消息数、最长的一条消息预览(前 30 字)、平均每轮 token(总 token ÷ 轮数)。全部数据从 session 和 model 现算(计算属性思维,Day 09)。

**参考答案(homework/stats_command.py 关键函数):**

```python
def do_stats(session: ChatSession, model) -> None:
    """会话统计:全部现算,不维护额外状态(状态越少 bug 越少)。"""
    user_msgs = [m for m in session.messages if m.role == "user"]
    ai_msgs = [m for m in session.messages if m.role == "assistant"]
    rounds = len(ai_msgs)                              # 一轮 = 一次成功的问答

    if not session.messages:
        print("暂无数据")
        return

    longest = max(session.messages, key=lambda m: len(m.content))
    tokens = model.count_usage()["tokens"]

    print(f"轮数 {rounds} | 用户消息 {len(user_msgs)} | AI 消息 {len(ai_msgs)}")
    print(f"最长消息([{longest.role}]):{longest.content[:30]}...")
    if rounds:
        print(f"平均每轮 {tokens / rounds:.0f} tokens")
```

## 第三部分:思考题(2 题)

**思考题 1:** 项目一的记忆是"全量重发"式的。假设一个用户和助手聊了 200 轮,列出这个方案此刻的三个具体痛点,并为每个痛点猜一个解决方向(Day 27 会验证你的猜想)。

**参考答案要点:** ①**成本**:每轮输入 token 包含全部历史,第 200 轮可能单次就要几万 token——方向:窗口截断(只发最近 N 轮)/摘要压缩(旧对话让模型总结成一段);②**上限**:迟早超过模型上下文窗口(128K)直接报错——方向:同上,外加把旧信息存向量库按需检索(这就是 RAG 思想反哺记忆);③**质量**:超长上下文里模型对中间内容的注意力下降("迷失在中间"现象)——方向:把关键信息(用户名字、偏好)提炼成结构化"用户画像"常驻 system。三个方向合起来就是 Day 27 的课表:窗口记忆、摘要记忆、持久化记忆。

**思考题 2:** 复盘全景表显示项目一"没有一个知识点是孤立的"。反过来想:如果让你**给两周课程挑一个刺**——哪个知识点的位置安排你认为可以更好?(自由回答,练习"对课程本身做工程评审"的元视角)

**参考答案示例方向:** 常见的有价值答案:①"正则(Day 11)可以更早,Day 02 清洗时就想要了"——反方:没有字符串方法的地基,正则会变成天书;②"类(Day 08)可以更晚,函数够用很久"——反方:chatlib 的演进需要时间发酵;③"异步(Day 13)太早了,没有场景"——反方:Day 23 FastAPI 前必须见过一面。**任何有理由的批评都比"都挺好"有价值**——对既有安排提出结构性意见,是高级工程师评审设计文档的日常。
