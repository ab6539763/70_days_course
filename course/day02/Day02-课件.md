# 上午 · 第一节(9:00 - 10:20):算术运算符与优先级

## 1.1 七个算术运算符:先补全昨天的算术拼图

昨天我们用了 `+ - * /`,今天补全剩下三个,凑齐七个:

```python
# ── 四个老朋友 ──────────────────────────────
print(10 + 3)     # 13   加
print(10 - 3)     # 7    减
print(10 * 3)     # 30   乘
print(10 / 3)     # 3.3333333333333335   除:结果永远是 float,哪怕整除
print(10 / 5)     # 2.0  ← 看!就算除得尽,也是 2.0 不是 2

# ── 三个新面孔 ──────────────────────────────
print(10 // 3)    # 3    整除(地板除):只要商的整数部分,向下取整
print(10 % 3)     # 1    取余(模运算):10 除以 3,余 1
print(10 ** 3)    # 1000 幂运算:10 的 3 次方
```

三个新运算符各自的用武之地,直接给业务场景:

**整除 `//` 和取余 `%` 是一对,经常搭配出现。** 经典场景:换算。

```python
# 场景:把"总分钟数"换算成"X 小时 Y 分钟"
total_minutes = 135
hours = total_minutes // 60      # 135 // 60 = 2      → 2 小时
minutes = total_minutes % 60     # 135 % 60 = 15      → 余 15 分钟
print(f"{total_minutes} 分钟 = {hours} 小时 {minutes} 分钟")   # 135 分钟 = 2 小时 15 分钟

# 场景:判断奇偶(明天 if 学完后的高频考题,今天先见一面)
# 偶数除以 2 余 0,奇数余 1
print(8 % 2)      # 0  → 8 是偶数
print(7 % 2)      # 1  → 7 是奇数
```

**取余在大模型开发里的真实出场**(提前剧透,眼熟即可):Day 28 做文档分块时,"每 500 字切一块,最后不足 500 字的算一块",块数的计算就要用 `//` 和 `%`;Day 24 做分页查询"每页 10 条,共 95 条,需要几页",同理。

**幂运算 `**` 的用武之地**:昨天 BMI 作业里的 `height * height`,今天可以写成 `height ** 2`;Day 20 学 Embedding 时,计算向量长度要用到平方和开方,开方就是 `** 0.5`:

```python
print(9 ** 0.5)     # 3.0   → 9 的 0.5 次方 = 根号 9
```

## 1.2 运算优先级:不报错的错误最危险

昨天 BMI 作业的"常见错误"里埋了一句话:`weight / height * height` 结果恒等于 weight,不报错但结果全错。今天正式讲清楚背后的规则——**运算优先级**。

Python 的算术优先级和数学课一致:

```
高 ──────────────────────────────► 低
()  >  **  >  * / // %  >  + -
括号     幂      乘除类      加减
同级运算:从左到右依次算(幂运算例外,从右到左)
```

用三个例子把规则钉死:

```python
# 例 1:乘除同级,从左到右
print(70 / 7 * 2)        # 20.0  → 先 70/7=10.0,再 10.0*2
# 如果你想要 70 / (7*2) = 5.0,必须自己加括号

# 例 2:先乘除后加减
print(3 + 4 * 2)         # 11    → 不是 14

# 例 3:昨天 BMI 的坑,现场复盘
weight, height = 70, 1.75          # 顺带学个新语法:一行给多个变量赋值
wrong = weight / height * height   # (70/1.75)*1.75 = 70.0  ← 恒等于体重!
right = weight / (height * height) # 70/3.0625 = 22.857...  ← 正确
print(wrong, right)
```

**工程师的实用守则:拿不准优先级就加括号。** 括号不要钱,而且让代码意图一目了然。真实项目代码里,`(a + b) * c` 这种"其实不必要"的括号随处可见——可读性优先于炫技,这是行业共识。

## 1.3 复合赋值运算符:程序员的懒人快捷键

一个变量在自己基础上更新,是编程里最高频的动作之一,Python 提供了缩写:

```python
count = 0
count = count + 1     # 完整写法:count 的新值 = 旧值 + 1
count += 1            # 缩写,与上一行完全等价
print(count)          # 2

# 全家福:每个算术运算符都有对应的复合赋值
total = 100
total -= 30      # total = total - 30   → 70
total *= 2       # total = total * 2    → 140
total //= 3      # total = total // 3   → 46
total %= 7       # total = total % 7    → 4
print(total)     # 4
```

`+=` 的两个未来出场点,先挂号:① 明天写循环时,计数器 `count += 1` 是标配;② Day 24 做流式输出时,把大模型吐出的字一段段拼起来:`answer += chunk`——ChatGPT 的打字机效果,幕后就是一个 `+=`。

## 1.4 字符串也能"加"和"乘":运算符重载初体验

昨天作业读程序题 1 已经埋过点:`"3" + "5"` 得 `"35"`。今天给这个现象一个正式名分——**同一个运算符,操作数类型不同,行为不同**,这叫运算符重载:

```python
# + 号的两副面孔
print(3 + 5)              # 8      数字:算术加法
print("3" + "5")          # 35     字符串:拼接
print("你好" + "世界")     # 你好世界

# * 号的两副面孔
print(3 * 5)              # 15     数字:乘法
print("-" * 20)           # --------------------  字符串 × 整数:重复拼接(昨天的分隔线!)

# 混搭会报错,Python 拒绝猜你的心思
# print("3" + 5)          # TypeError: can only concatenate str (not "int") to str
# 想拼必须显式转换:
print("3" + str(5))       # 35
print(int("3") + 5)       # 8
```

**为什么 Python 遇到 `"3" + 5` 宁可报错也不猜?** 因为两种猜法都说得通(`"35"` 还是 `8`?),猜错的代价比报错大得多。这体现了 Python 之禅里的一条:**"面对歧义,拒绝猜测的诱惑"**。对比 JavaScript(`"3" + 5` 得 `"35"`,`"3" - 5` 得 `-2`,行为精分),你会感激 Python 的严格——报错是朋友,它在你犯错的第一现场就拦住你。

## 1.5 比较运算符:让程序学会"提问"

现在进入今天上午的重头戏。到昨天为止,我们的程序只会"陈述"(算出结果、输出内容),不会"提问"。比较运算符让程序能问出"是不是"、"大不大"这类问题,答案只有两个:`True` 或 `False`(昨天学的 bool 类型,今天终于知道它是干嘛的了):

```python
age = 28

print(age > 18)      # True    大于
print(age < 18)      # False   小于
print(age >= 28)     # True    大于等于(注意顺序:>= 不能写成 =>)
print(age <= 27)     # False   小于等于
print(age == 28)     # True    等于 —— 双等号!
print(age != 30)     # True    不等于
```

**全场最重要的一个坑:`=` 和 `==` 是两码事。**

```python
age = 28       # 一个等号:赋值。"把 28 存进 age"——是命令
age == 28      # 两个等号:比较。"age 等于 28 吗?"——是提问,得到 True/False
```

初学者把 `if age = 28` 写错的概率接近 100%(明天你就会亲身验证)。好消息是 Python 会直接报 SyntaxError 拦住你,坏消息是有些语言(如 C)不拦,酿成过无数事故。从今天起在心里默念:**赋值一个等,比较两个等**。

比较运算符同样支持字符串:

```python
print("abc" == "abc")     # True
print("abc" == "ABC")     # False  大小写敏感!"张三" 和 " 张三 " 也不相等(空格也是字符)
print("apple" < "banana") # True   字符串比较按"字典序":逐字符比编码大小
```

`"abc" == "ABC"` 是 False 这件事,直接呼应昨天的脏数据问题:如果用户表里存的是 `"SHANGHAI"`,查询时用 `"shanghai"`,一条都查不到。**所以工程实践中,比较字符串前通常先统一大小写**——下午学的 `lower()` 就是干这个的,伏笔埋好了。

## 1.6 逻辑运算符:把多个问题连起来问

单个提问不够用。"年龄合法"其实是两个问题:大于等于 0 **并且** 小于等于 120。逻辑运算符负责组合提问:

```python
age = 28

# and:两边都 True 才 True("并且")
print(age >= 0 and age <= 120)    # True   年龄在合法区间
print(age > 18 and age < 25)      # False  28 不在 18~25 之间

# or:任意一边 True 就 True("或者")
vip = False
points = 12000
print(vip or points > 10000)      # True   是 VIP 或积分过万,享受特权

# not:取反("不是")
is_banned = False
print(not is_banned)              # True   没被封禁

# Python 特色语法糖:区间判断可以连写(数学写法)
print(0 <= age <= 120)            # True   等价于 age >= 0 and age <= 120,更好读
```

三个运算符的优先级:`not > and > or`。同样的建议:**组合复杂时加括号**,`(a and b) or (c and d)` 远比裸写好读。

用一个真实场景把三者串起来——这段"伪代码"就是明天 if 语句实操的预告:

```python
# 场景:大模型 API 网关的请求准入检查(Day 24 会真的写它)
api_key_valid = True       # API Key 是否有效
balance = 3.50             # 账户余额(元)
is_banned = False          # 是否被封禁

# 放行条件:Key 有效 且 (余额充足 或 在免费额度内) 且 没被封禁
free_quota_left = True
allowed = api_key_valid and (balance > 0 or free_quota_left) and not is_banned
print(allowed)             # True —— 明天学了 if,就能"根据 allowed 决定放行还是拒绝"
```

## 1.7 真值的隐藏规则:空即是 False

Python 有个优雅的设定:**任何值都能被当作 True/False 来看待**,规则一句话——"空的、零的算 False,其他都算 True":

```python
print(bool(0))         # False    数字 0
print(bool(0.0))       # False
print(bool(""))        # False    空字符串
print(bool("hi"))      # True     非空字符串
print(bool(" "))       # True     ⚠️ 空格不是空!它是一个字符
print(bool(42))        # True
print(bool(-1))        # True     负数也是 True(非零即真)
```

这个规则今天先混个脸熟,明天写 `if user_input:`(用户输入非空才处理)时它会正式上岗。注意第五行的坑:`" "` 含一个空格,是 True——所以判断"用户没输入东西"之前,得先用下午学的 `strip()` 把空格剥掉,两天的知识在这里咬合上了。

# 上午 · 第二节(10:30 - 12:00):字符串的解剖学——索引与切片

## 2.1 字符串是字符的序列:先建立空间感

把字符串想象成**一排带编号的储物柜**,每个柜子放一个字符。编号(术语叫**索引/index**)从 **0** 开始——不是 1,这是几乎所有编程语言的共同约定,原因可以追溯到 C 语言的内存偏移量设计,今天只需记住并习惯它:

```
字符串  s = "DeepSeek"

正向索引:   0    1    2    3    4    5    6    7
字符:      D    e    e    p    S    e    e    k
反向索引:  -8   -7   -6   -5   -4   -3   -2   -1
```

```python
s = "DeepSeek"

# ── 索引:取单个字符 ──────────────────────
print(s[0])       # D    第一个字符(编号 0!)
print(s[4])       # S
print(s[-1])      # k    倒数第一个:负索引从右往左数,-1 是最后一个
print(s[-4])      # S

# 越界会报错:
# print(s[8])     # IndexError: string index out of range
#                 # 8 个字符,合法索引是 0~7,没有 8 号柜子

# ── len():量长度,今天的新内置函数 ─────────
print(len(s))             # 8
print(len("你好,世界"))    # 5    中文字符也是一个算一个(逗号也算)
print(len(""))            # 0    空字符串长度为 0
```

`len()` 的未来出场点:Day 15 估算文本的 token 数之前先看字符数;Day 28 文档分块按 `len(chunk)` 控制块大小。它可能是你未来用得最多的内置函数之一。

## 2.2 切片:一刀切出子串

索引取一个字符,**切片(slice)取一段**。语法 `s[起点:终点:步长]`,三个参数都可省略。核心规则只有一条,必须刻进 DNA:**含头不含尾**——起点位置的字符要,终点位置的字符不要:

```python
s = "DeepSeek"

print(s[0:4])      # Deep     取 0,1,2,3 号 —— 4 号不要!含头不含尾
print(s[4:8])      # Seek     取 4,5,6,7 号
print(s[:4])       # Deep     起点省略 = 从头开始
print(s[4:])       # Seek     终点省略 = 一直到尾
print(s[:])        # DeepSeek 全都要(复制一份)
print(s[-4:])      # Seek     倒数 4 个:负索引切片,取"最后 N 个"的惯用写法
print(s[::2])      # DeSe     步长 2:每隔一个取一个(0,2,4,6 号)
print(s[::-1])     # keeSpeeD 步长 -1:整个倒过来 —— 字符串反转的经典一行流
```

**为什么"含头不含尾"是好设计?** 两个好处:① `s[:4]` 和 `s[4:]` 正好无缝拼回原串,切分点清晰不重叠;② `s[0:4]` 的长度就是 `4 - 0 = 4`,终点减起点即长度,心算友好。习惯之后你会回不去的。

切片的真实业务场景,每个都值得抄进笔记:

```python
# 场景 1:手机号脱敏(显示前 3 位和后 4 位,中间打码)
phone = "13812345678"
masked = phone[:3] + "****" + phone[-4:]

# 【伏笔】Day 57 讲大模型应用安全时,"敏感信息脱敏"是必做项,核心就是这行

# (更严谨的做法用 split(".") 或 pathlib,下午和 Day 11 会讲)

# 场景 3:超长文本截断预览
article = "大模型正在深刻改变软件开发的方式,应用层开发者迎来了历史性机遇……"
```

## 2.3 字符串不可变:一个会影响写法的重要事实

试着修改字符串的一个字符:

```python
s = "DeepSeek"
# s[0] = "d"      # TypeError: 'str' object does not support item assignment
```

报错了。**Python 的字符串是不可变的(immutable)**:一旦创建,内容永不改变。所有"看起来修改了字符串"的操作,实际都是**造了一个新字符串**:

```python
s = "DeepSeek"
s2 = s.lower()        # lower() 没有改动 s,而是新造了一个全小写的字符串
print(s)              # DeepSeek   原串安然无恙
print(s2)             # deepseek   新串
```

这个事实推导出一个**今天下午会反复用到的写法规则**:字符串方法的结果必须接住(赋值给变量),否则等于白调用:

```python
text = "  hello  "
text.strip()          # ❌ 白调用:strip 的结果没人接,原地蒸发
print(text)           # "  hello  "  空格还在!

text = text.strip()   # ✅ 用变量接住新字符串(通常就赋回原变量)
print(text)           # "hello"
```

**"调用了方法但没赋值回去"是今天下午实操的头号预定错误**,先打好预防针。至于 Python 为什么把字符串设计成不可变(线程安全、可作字典键、内存优化),Day 05 讲字典时会回收这个伏笔——字典的键必须是不可变类型。

# 下午 · 第一节(14:00 - 15:40):字符串方法——文本处理的瑞士军刀

## 3.1 方法 vs 函数:先弄清一个叫法

上午用的 `len(s)` 是**函数**(独立存在,把东西递给它);下面要学的 `s.strip()` 是**方法**(长在字符串身上,用点号调用)。类比:`len()` 像公共体重秤,谁都能上去称;`.strip()` 像字符串自带的技能,"字符串,请你自己去掉两端空格"。为什么有的功能是函数、有的是方法?这是面向对象的设计哲学,Day 08 讲类的时候你会彻底明白,今天先会用。

一个探索技巧送给你:在 VS Code 里输入 `s.` 之后停顿,自动弹出的列表就是字符串的全部方法(七十多个)。我们今天精讲最常用的十几个,分四组。

## 3.2 第一组:清洗三剑客(strip / lower / upper)

昨天作业埋的钩子,现在正式收线:

```python
# ── strip():剥掉两端的空白字符(空格、换行 \n、制表符 \t) ──
raw_name = "  张三  \n"
print(f"[{raw_name}]")             # [  张三  
#                                  # ]         ← 连换行都进去了,很丑
clean_name = raw_name.strip()
print(f"[{clean_name}]")           # [张三]     ← 干净了

# 注意:strip 只管两端,不动中间
print("  New York  ".strip())      # "New York"  中间的空格保留(它是合法的)

# 变体:只剥左边 / 只剥右边
print("  hi  ".lstrip() + "|")     # "hi  |"    left strip
print("  hi  ".rstrip() + "|")     # "  hi|"    right strip

# strip 还能指定要剥的字符
print("###标题###".strip("#"))     # "标题"     剥掉两端所有 #

# ── lower() / upper():统一大小写 ──
city = "SHANGHAI"
print(city.lower())                # shanghai
print(city.upper())                # SHANGHAI
print("Beijing".capitalize())      # Beijing → 首字母大写其余小写
print("hello world".title())       # Hello World → 每个单词首字母大写

# ── 组合拳:清洗的标准姿势(链式调用,从左到右依次执行) ──
user_input = "  YES  "
answer = user_input.strip().lower()    # 先剥空格,再转小写
print(answer == "yes")                 # True
# 这一行是所有"判断用户输入"代码的标准前置操作:
# 无论用户输入 "yes"、"YES  "、" Yes",清洗后都能对上
# 【伏笔】Day 14 的 AI 助手判断用户是否输入了 /exit 指令,就用这一招
```

**链式调用**是新语法,值得单独说一句:`a.strip().lower()` 的执行顺序是——`a.strip()` 返回一个新字符串,紧接着对这个新字符串调用 `.lower()`,再返回新字符串。像流水线,每站加工完交给下一站。链不要太长(三个以内),否则可读性下降。

## 3.3 第二组:查找与判断(in / find / startswith / endswith)

```python
text = "Python 是大模型应用开发的第一语言"

# ── in:最常用的"包含"判断,返回 bool ──
print("大模型" in text)            # True
print("Java" in text)              # False
print("Java" not in text)         # True   not in 是它的反义词

# ── find():不仅判断,还告诉你位置 ──
print(text.find("大模型"))         # 8     首次出现的索引
print(text.find("Java"))           # -1    找不到返回 -1(不报错)
# 姊妹方法 index() 功能相同但找不到会抛 ValueError,日常首选 find

# ── startswith / endswith:判断开头结尾,返回 bool ──
filename = "report_2026.pdf"
print(filename.endswith(".pdf"))       # True
print(filename.startswith("report"))   # True
# 一次判断多个候选:传元组(Day 04 会正式学元组,今天先照抄)
print(filename.endswith((".pdf", ".docx", ".md")))    # True

# ── count():数出现次数 ──
log = "ERROR: timeout. ERROR: retry failed. INFO: done"
print(log.count("ERROR"))          # 2
```

业务出场预告:`in` 是 Day 03 敏感词过滤、Day 18 检查模型输出是否包含违禁内容的主力;`endswith` 是 Day 28 文档加载器路由(".pdf 走 PDF 解析,.md 走 Markdown 解析")的判断依据;`startswith` 是 Day 14 判断用户输入是不是以 `/` 开头的指令的核心。**今天学的每个方法,都标好了未来的座位。**

## 3.4 第三组:拆与拼(split / join)——重要程度五颗星

这两个方法是一对互逆操作,是文本处理的心脏,必须练到条件反射:

```python
# ── split(分隔符):按分隔符把字符串拆成"列表" ──
csv_line = "张三,28,上海,大模型工程师"
fields = csv_line.split(",")
print(fields)          # ['张三', '28', '上海', '大模型工程师']
# 得到的是"列表(list)"——明天 Day 04 的主角,今天先直观感受:
# 列表就是有序的一排值,可以用索引取:fields[0] 是 '张三'
print(fields[0], fields[2])       # 张三 上海

# split() 不传参数:按任意空白拆(连续空格、换行都算一个分隔),最常用
sentence = "the   quick  brown   fox"
print(sentence.split())           # ['the', 'quick', 'brown', 'fox']  多余空格自动吞掉

# 按换行拆:处理多行文本的标准动作
doc = "第一行\n第二行\n第三行"
print(doc.split("\n"))            # ['第一行', '第二行', '第三行']
# (splitlines() 方法效果类似且更健壮,Day 11 读文件时会用到)

# ── join:split 的逆操作,把列表拼回字符串 ──
# 语法有点反直觉:是"分隔符.join(列表)",分隔符在前!
words = ["Python", "LangChain", "RAG", "Agent"]
print(" → ".join(words))          # Python → LangChain → RAG → Agent
print(", ".join(words))           # Python, LangChain, RAG, Agent
print("".join(["a", "b", "c"]))   # abc   空分隔符 = 无缝拼接
```

**为什么 join 长在分隔符身上而不是列表身上?** 因为列表里可以装任何类型,但 join 只对字符串有意义;把方法放在字符串(分隔符)上,职责更清晰。读法建议:`" → ".join(words)` 读作"用箭头,把 words 串起来"。

split + join 组合拳的威力,一行代码解决真实需求:

```python
# 场景:把用户输入的"多余空格"规范化成单个空格
messy = "大模型   应用    开发"
clean = " ".join(messy.split())    # 先按空白拆散(吞掉多余空格),再用单空格拼回
print(clean)                       # 大模型 应用 开发
# 【伏笔】这一行是 Day 28 文档清洗流水线的固定工序之一
```

## 3.5 第四组:替换(replace)

```python
# ── replace(旧, 新):把所有旧子串换成新子串 ──
text = "我喜欢Java,Java是最好的语言"
new_text = text.replace("Java", "Python")
print(new_text)        # 我喜欢Python,Python是最好的语言 —— 注意:所有出现都换!
print(text)            # 原串没变(字符串不可变,replace 返回新串)

# 只换前 N 个:第三个参数
print(text.replace("Java", "Python", 1))   # 我喜欢Python,Java是最好的语言

# replace 删东西:换成空字符串
phone = "138-1234-5678"
print(phone.replace("-", ""))               # 13812345678

# 敏感词处理的雏形(下午实操的核心逻辑)
comment = "这个傻子产品真难用"
print(comment.replace("傻子", "**"))        # 这个**产品真难用
```

## 3.6 方法速查总表(课堂笔记素材)

| 方法 | 作用 | 返回 | 一句话记忆 |
|------|------|------|-----------|
| `s.strip()` | 剥两端空白 | 新 str | 进系统前先洗手 |
| `s.lower()` / `s.upper()` | 统一大小写 | 新 str | 比较前先统一 |
| `x in s` | 是否包含 | bool | 最常用的判断 |
| `s.find(x)` | 首次出现位置 | int(无=-1) | 找不到不报错 |
| `s.startswith(x)` / `s.endswith(x)` | 判断头尾 | bool | 指令/扩展名路由 |
| `s.count(x)` | 出现次数 | int | 统计词频雏形 |
| `s.split(sep)` | 拆成列表 | list | 拆 |
| `sep.join(lst)` | 列表拼回字符串 | str | 拼(分隔符在前!) |
| `s.replace(a, b)` | 全部替换 | 新 str | 也能用来删 |
| `len(s)` | 长度(函数) | int | 中文一个算一个 |

**共同铁律:所有方法都不修改原字符串,结果必须赋值接住。**

## 3.7 f-string 补完:对齐与填充

昨天学了 `:.2f`、`:,`、`:.1%`,今天补上对齐控制,凑齐 f-string 的完整技能树。这是让输出"像产品"而不是"像草稿"的关键:

```python
# 语法:{变量:填充字符 对齐方向 总宽度}
# 对齐方向:< 左对齐   > 右对齐   ^ 居中
name = "张三"
print(f"[{name:<10}]")     # [张三        ]   左对齐,总宽 10
print(f"[{name:>10}]")     # [        张三]   右对齐
print(f"[{name:^10}]")     # [    张三    ]   居中
print(f"[{name:*^10}]")    # [****张三****]   用 * 填充的居中

# 实战:打印一张对齐的表格(昨天的卡片输出可以退休了)
print(f"{'模型':<12}{'输入价':>8}{'输出价':>8}")
print("-" * 28)
print(f"{'deepseek-chat':<12}{1.0:>8.2f}{4.0:>8.2f}")
print(f"{'gpt-4o':<12}{18.0:>8.2f}{72.0:>8.2f}")
# 输出:
# 模型            输入价    输出价
# ----------------------------
# deepseek-chat    1.00    4.00
# gpt-4o          18.00   72.00
```

> 细节说明:中文字符在终端里占两个显示宽度,而 f-string 按"字符个数"对齐,所以中英文混排的表格会略有错位。完美解决需要第三方库,课程阶段接受这个小瑕疵,知道原因即可。

### v2:加入敏感词替换(F3),并统计替换次数

```python
# =============================================
# 用户评论清洗工具 v2
# 新增:F3 敏感词替换 + 替换次数统计
# 关键思路:替换前先用 count() 数一遍,数据才有据可查
# =============================================

raw_comment = """   这个AI客服真是垃圾,回答驴唇不对马嘴!
客服电话13812345678也打不通,   NO ONE CARES!
真是气死我了,做这个产品的都是傻子   
"""

step1 = raw_comment.strip()
step2 = step1.lower()

# ---- F3:敏感词替换 ----
# 敏感词逐个处理:先数出现次数(报告要用),再替换成等长的 *
# "等长"是产品细节:**比直接删除更能让人看出"这里有词被处理了"
# 明天(Day 03)学了 for 循环,这三段重复代码会被压缩成三行——
# 今天先忍受重复,亲身体会"没有循环的痛",明天的知识才有滋味

count_1 = step2.count("垃圾")            # 数"垃圾"出现几次
step3 = step2.replace("垃圾", "**")      # 替换为等长的两个星号

count_2 = step3.count("傻子")            # 注意:在 step3 上继续数和换
step3 = step3.replace("傻子", "**")      # 结果赋回 step3(累积加工)

count_3 = step3.count("废物")
step3 = step3.replace("废物", "**")

total_replaced = count_1 + count_2 + count_3    # 报告用:总替换词数

print(f"[{step3}]")
print(f"共处理敏感词 {total_replaced} 个")
```

停下来观察一个细节:第二次替换开始,我们是**在 step3 上继续加工并赋回 step3**(`step3 = step3.replace(...)`)。这就是上午"字符串不可变 → 结果必须接住"规则的实战——如果写成 `step3.replace("傻子", "**")` 不赋值,这一步就白做了。**现在,请你故意把某一行的赋值去掉,运行看看结果,亲眼见一次这个 bug 的样子**——课堂上主动制造一次 bug,好过将来生产环境被动遇到。

### v3:空格规范化(F4)+ 完整清洗报告

```python
# =============================================
# 用户评论清洗工具 v3
# 新增:F4 空格规范化 + 对齐的清洗报告
# 关键技巧:" ".join(x.split()) 组合拳、f-string 对齐
# =============================================

raw_comment = """   这个AI客服真是垃圾,回答驴唇不对马嘴!
客服电话13812345678也打不通,   NO ONE CARES!

count_2 = step3.count("傻子")

count_3 = step3.count("废物")
step3 = step3.replace("废物", "**")

# " ".join(...) = 用单个空格拼回
# 一进一出,所有"多余空白"都被规范成单个空格
# 副作用说明:换行也会被拍平成空格——对"单条评论"这是可接受的;

# ---- 清洗报告 ----

print(f"{'原文长度':<10}{len(raw_comment)} 字符")
print(f"{'净文长度':<10}{len(clean_comment)} 字符")
print(f"{'敏感词处理':<10}{total_replaced} 个")
print("-" * 46)
print("净文预览:")
print(clean_comment)
print("=" * 46)
```

### v4:附加功能——手机号提取与脱敏

需求文档最后一条:提取评论中的手机号并脱敏。**先想再写**:评论是一长串字符,手机号是其中连续 11 位数字,怎么定位它?今天工具箱里最合适的是 `find()`:

```python
# =============================================
# 用户评论清洗工具 v4(最终版)
# 新增:手机号提取与脱敏
# 思路:find("1") 有局限(如果"1"先出现在别处会误判),
#       今天用"找 138 前缀"的简化方案,并诚实标注局限——
#       完美方案是 Day 11 的正则表达式,这里再埋一个钩子
# =============================================

raw_comment = """   这个AI客服真是垃圾,回答驴唇不对马嘴!
客服电话13812345678也打不通,   NO ONE CARES!
真是气死我了,做这个产品的都是傻子   
"""

# ---- 流水线 F1~F4(同 v3,压缩书写) ----
text = raw_comment.strip().lower()               # F1+F2 链式调用一行完成

count_total = text.count("垃圾") + text.count("傻子") + text.count("废物")
text = text.replace("垃圾", "**").replace("傻子", "**").replace("废物", "**")   # F3 链式替换

clean_comment = " ".join(text.split())           # F4

# ---- 附加:手机号提取与脱敏 ----
# 第一步:定位。find 返回 "138" 首次出现的索引;-1 表示没找到
pos = clean_comment.find("138")
# 第二步:切片取出从该位置起的 11 个字符(含头不含尾:pos 到 pos+11)
phone = clean_comment[pos:pos + 11]
# 第三步:脱敏——昨天预告过的经典切片拼接
masked_phone = phone[:3] + "****" + phone[-4:]
# 第四步:把评论里的明文手机号也替换成脱敏版(隐私不落地)
clean_comment = clean_comment.replace(phone, masked_phone)

# ---- 清洗报告 ----
print("=" * 46)
print(f"{'清洗报告':^42}")
print("=" * 46)
print(f"{'原文长度':<10}{len(raw_comment)} 字符")
print(f"{'净文长度':<10}{len(clean_comment)} 字符")
print(f"{'敏感词处理':<10}{count_total} 个")
print(f"{'手机号脱敏':<10}{masked_phone}")
print("-" * 46)
print("净文预览:")
print(clean_comment)
print("=" * 46)
```

# 【常见错误与排错手册】Day 02 专属篇

> 以下八个错误,取自历届学员当天实操的真实翻车现场。建议对着自己的代码逐条排查一遍。

**错误 1:方法调用不赋值,清洗"没生效"。**

```python
text = "  hello  "
text.strip()              # 结果没人接
print(text)               # 还是 "  hello  "
```

症状:代码没报错,但输出和没清洗一样。排查:检查每一个字符串方法调用,左边有没有 `xxx =`。这是今天出现率最高的错误,而且**不报错**,只能靠输出结果倒推。养成习惯:写完 `.strip()` 之类的方法,手指条件反射地检查行首有没有赋值。

**错误 2:`join` 用反了主语。**

```python
words = ["a", "b", "c"]
# words.join("-")         # AttributeError: 'list' object has no attribute 'join'
"-".join(words)           # 正确:分隔符在前
```

症状:`AttributeError: 'list' object has no attribute 'join'`。读报错:列表对象没有 join 这个方法——因为 join 长在字符串身上。

**错误 3:切片"含头不含尾"记反,少一个字符。**

```python
s = "LangChain"
print(s[0:4])     # Lang —— 想要 LangC 的话,终点要写 5,不是 4
```

症状:不报错,但结果总是"差一个"。这类错误行话叫 off-by-one(差一错误),是全世界程序员的经典错误。口诀再念一遍:**起点要,终点不要;终点减起点等于长度**。

**错误 4:`find` 返回 -1 没检查,切片切出诡异结果。**

```python
text = "没有手机号的评论"
pos = text.find("138")        # 找不到,返回 -1
phone = text[pos:pos + 11]    # text[-1:10] —— 负索引开切,结果是空串或意外内容
```

症状:不报错,但提取出来的"手机号"是空的或乱的。原因:`find` 找不到时返回 -1,而 -1 是合法索引(倒数第一个)!所以 `find` 之后**必须先检查是否为 -1** 再使用——用什么检查?if 语句,明天的内容。今天先记住这个坑的存在。

**错误 5:比较字符串忘了先统一大小写/去空格。**

```python
user_cmd = input("输入 yes 继续:")     # 用户输入了 "YES "(带尾巴空格)
print(user_cmd == "yes")               # False!
print(user_cmd.strip().lower() == "yes")   # True,标准姿势
```

**错误 6:`split(",")` 与中文逗号错位。**

```python
data = "张三,28,上海"          # 注意:这是中文全角逗号!
print(data.split(","))         # ['张三,28,上海'] —— 没拆开!英文逗号找不到
print(data.split(","))         # ['张三', '28', '上海'] —— 用中文逗号才拆得开
```

症状:split 返回的列表只有一个元素。原因:分隔符和数据里的逗号"长得像但不是同一个字符"。处理真实中文数据时,先确认标点是全角还是半角;必要时先 `replace(",", ",")` 统一。

**错误 7:反斜杠引发的意外转义。**

```python
path = "C:\notes\day02"        # \n 被解释成换行!输出会断行
path = r"C:\notes\day02"       # 解法 1:r 前缀 = 原始字符串,反斜杠不转义
path = "C:/notes/day02"        # 解法 2:正斜杠,Windows 也认
```

`\n` 是换行、`\t` 是制表符,这类"反斜杠+字母"叫转义字符。写 Windows 路径时高发,记住 r 前缀这个解法,Day 11 文件操作时救命用。

**错误 8:f-string 大括号想输出本身。**

```python
name = "张三"
print(f"JSON 格式:{{'name': '{name}'}}")    # 双写大括号 = 输出一个真的大括号
# 输出:JSON 格式:{'name': '张三'}
```

f-string 里想输出字面大括号,要写成 `{{` 和 `}}`。Day 18 要求模型"输出 JSON 格式"的 Prompt 里全是大括号,这个技巧到时是刚需。

# 【附录】课堂答疑实录(晚自习整理)

**问 1:`10 / 5` 为什么是 2.0 不是 2?感觉很多余。**

答:这是 Python 3 的刻意设计,叫"除法结果类型一致性":`/` 的结果**永远**是 float,不管除不除得尽。好处是可预测——你写代码时永远知道 `a / b` 是 float,不用猜。如果要整数,显式用 `//`。对比 Python 2 时代 `10 / 3` 得 3(静默丢掉小数),坑过无数人,Python 3 修正了它。顺便记一个工程含义:钱、token 数这类要精确的量,尽量用整数运算(以"分"、"个"为单位),float 有精度误差(试试 `0.1 + 0.2`,结果是 0.30000000000000004——这不是 bug,是所有语言共有的浮点数二进制表示问题,Day 05 讲 JSON 时会再提)。

**问 2:`and` / `or` 为什么不用 `&&` / `||`?我看别的语言都是符号。**

答:Python 的设计哲学是"代码应该接近自然语言"。`if age > 18 and has_id:` 读出来就是一句英语。注意 Python 里 `&` 和 `|` 也存在,但那是位运算符(以后 Day 33 混合检索里 `|` 会以另一个身份——LangChain 管道符——出现),初学阶段用错会得到诡异结果,请只用 `and` / `or` / `not`。

**问 3:切片为什么不会越界报错?`s[2:100]` 居然能跑?**

答:好观察!索引越界报 IndexError(`s[100]` 必炸),但**切片越界不报错**,`s = "abc"; s[2:100]` 安静地返回 `"c"`——切片的语义是"尽力而为,有多少给多少"。这是刻意设计:切片常用于"取前 N 个"(`s[:100]`),如果字符串不足 100 也能安全返回全部,免去每次先检查长度。Day 27 截断对话历史时,这个特性让代码简洁很多。

**问 4:方法名记不住怎么办?strip、split、splitlines 长得都像。**

答:三个建议。① 不要背,用 VS Code 的自动补全:输入 `s.` 停一下,候选列表+文档就出来了,工程师都这么干;② 记"锚点词":strip 是"剥"(两端)、split 是"劈"(拆开)、join 是"串"(拼回),中文锚点比英文好记;③ 高频的那十个,这周每天的作业都会逼你用,周五(Day 05)前自然长进肌肉。真实工作里,记住"有这个功能存在"比记住拼写重要——拼写交给补全和搜索。

**问 5:为什么 Python 字符串要设计成不可变?改一个字符还得造新串,不浪费吗?**

答:三个换来的好处。① 安全:字符串在程序里到处传递(当参数、当配置、当字典的键),如果可变,A 处偷偷改了,B 处就遭殃——不可变让"传出去的字符串永远不会被别人改"成为保证;② 可哈希:Day 05 会学字典,字典的键必须"值恒定",不可变是前提;③ 性能:Python 对短字符串做了缓存复用(驻留机制),前提也是不可变。至于"浪费"——对少量操作无感;真有海量拼接需求时用 `"".join(列表)` 一次成串(这也是为什么 join 重要)。这个问题问得好,Day 04 会看到"可变"的列表在这些场景的对照表现。

**问 6:今天的清洗工具,真实公司里会写成什么样?**

答:骨架一样,包装升级。真实版本会:把每道工序写成独立函数(Day 06)、违禁词从配置文件读入而不是写死(Day 11)、用正则表达式做手机号提取(Day 11)、批量处理一个文件夹的评论文件(Day 11)、清洗规则可配置开关(Day 10 的包结构)、加异常处理防单条脏数据搞崩整批任务(Day 10)。注意到了吗——**全是本周和下周的课**。Day 11 的实操"批量文档读取与关键词统计",就是今天工具的企业完全体。

**问 7:作业里 Prompt 模板用 replace 填充,和 f-string 到底差在哪?**

答:时机。f-string 在**代码运行到那一行的瞬间**就把值填死了,所以模板和值必须同时在场;replace 方案里模板只是普通字符串,可以存在文件里、数据库里、由产品经理在后台编辑,**运行时**才和值会合。生产系统的 Prompt 几乎都是"先存后填"——运营要改 Prompt 文案,总不能每次都改代码重新上线吧?LangChain 的 PromptTemplate(Day 25)、本课程毕业设计里的 Prompt 管理,走的都是这条路。今天这道作业题,是你第一次接触"配置与代码分离"这个工程思想。

**问 8:昨天的个人信息卡片,今天学的东西能马上用上吗?**

答:能,而且强烈建议今晚就动手(不算作业,算加餐):给卡片程序的所有 input 加上 `.strip()`,姓名加 `.title()`(如果是拼音),城市统一 `.lower()` 后再 `.capitalize()`,输出表格改用今天的对齐语法。改完你会发现昨天的程序"变结实了"——**每天用新知识回头加固旧项目**,这个习惯保持 70 天,Day 14 的项目一你会异常轻松。

# 【课堂笔记】Day 02 知识点速查表

**七个算术运算符**
`+ - * /`(除法结果永远 float)、`//` 整除、`%` 取余(奇偶/换算)、`**` 幂(`** 0.5` = 开方)
优先级:`()` > `**` > `* / // %` > `+ -`;同级从左到右;**拿不准就加括号**

**复合赋值**:`+= -= *= //= %=`;`answer += chunk` 是未来流式输出的心脏

**比较运算符**:`> < >= <= == !=`;**赋值一个等,比较两个等**;字符串比较大小写敏感
**逻辑运算符**:`and`(都真才真)、`or`(一真即真)、`not`(取反);优先级 not > and > or
**真值规则**:空/零为 False(`0`、`""`、`0.0`),其余 True;`" "` 是 True(空格是字符!)

**索引与切片**
- 索引从 0 开始;`s[-1]` 最后一个;越界 IndexError
- 切片 `s[起:止:步]`,**含头不含尾**;`s[:3]` 前三个、`s[-4:]` 后四个、`s[::-1]` 反转
- 手机号脱敏:`phone[:3] + "****" + phone[-4:]`

**字符串不可变**:所有方法返回新串,**必须赋值接住**:`text = text.strip()`

**方法四组**
1. 清洗:`strip / lstrip / rstrip / lower / upper`;标准姿势 `x.strip().lower()`
2. 查找:`in`(bool)、`find`(索引,无=-1)、`startswith / endswith`、`count`
3. 拆拼:`s.split(sep)` → 列表;`sep.join(lst)` → 字符串(**分隔符在前**);空格规范化 `" ".join(x.split())`
4. 替换:`s.replace(旧, 新)` 全部替换;替换成 `""` 即删除

**f-string 对齐**:`{x:<10}` 左、`{x:>10}` 右、`{x:^10}` 居中、`{x:*^10}` 带填充

**流水线思想**:数据流过一排加工站,每站只做一件事——Day 26/28 的架构原型

**今日高频错误**
- 方法调用不赋值 → 清洗"没生效"
- `=` 与 `==` 混用 → SyntaxError(明天 if 里高发)
- 切片忘了"含头不含尾" → 少一个字符
- `join` 写成 `lst.join(sep)` → AttributeError(列表没有 join 方法)
