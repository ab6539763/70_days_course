**6. 把列表 `["a", "b", "c"]` 拼成 `"a-b-c"`,正确写法是?**
A. `["a","b","c"].join("-")`
B. `"-".join(["a", "b", "c"])`
C. `join("-", ["a","b","c"])`
D. `["a","b","c"].split("-")`

**7. `bool(" ")` 的值是?**
A. `False`  B. `True`  C. `None`  D. 报错

**8. `"Python".find("th")` 的返回值是?**
A. `2`  B. `3`  C. `True`  D. `-1`

A. `ababcc`  B. `abababc`  C. `ababab c`  D. 报错

**10. 下列哪个能正确判断变量 `score` 在 60 到 100 之间(含端点)?**
A. `60 <= score <= 100`
B. `score >= 60 and score <= 100`
C. A 和 B 都可以
D. `score >= 60 or score <= 100`

### 选择题答案与解析

**1. B。** `//` 整除只取商的整数部分(17÷5=3.4 → 3);`%` 取余(17 - 3×5 = 2)。
**2. B。** `/` 除法的结果**永远是 float**,哪怕除得尽也是 `2.0`。想要整数结果用 `//`。
**3. B。** 偶数除以 2 余 0。A 是除法(`n/2==0` 只有 n=0 才成立);C 是整除,`n//2==0` 表示 n 是 0 或 1;D 是平方。
**4. A。** 含头不含尾:取索引 4,5,6,7,8 号字符。`LangChain` 中 4 号是 `C`,到 8 号 `n`,即 `Chain`。
**5. B。** 字符串不可变!`s.upper()` 返回了新字符串 `"HELLO"`,但没人接住,原地蒸发,`s` 依然是 `"hello"`。想生效必须 `s = s.upper()`。这是今天的头号考点。
**6. B。** `join` 长在**分隔符**身上,列表作参数。A 会报 `AttributeError`(列表没有 join 方法);D 的 split 是拆不是拼。
**7. B。** 空格是一个真实的字符,`" "` 长度为 1,非空即真。真正的空字符串 `""` 才是 False。所以判断"用户没输入"要先 `strip()` 再判断。
**8. A。** `find` 返回子串**首次出现的索引**:P-y-t,`t` 在 2 号位。找不到才返回 -1。
**9. B。** 先算乘法(优先级高):`"ab"*3` → `"ababab"`,再拼接 `"c"`。
**10. C。** Python 支持数学式连写 `60 <= score <= 100`,与 and 写法完全等价,更好读。D 是永真式(任何数都满足"大于等于60 **或** 小于等于100"),典型逻辑错误。

2. 判断字符串变量 `fname` 是否以 `.pdf` 结尾:`fname.________(".pdf")`。
3. 把 `"  Hello World  "` 清洗成 `"hello world"` 的链式写法:________。
4. 字符串反转的切片一行流:`s________`。

### 填空题答案

1. `//` 和 `%`(4 小时 7 分钟)
2. `endswith`
3. `"  Hello World  ".strip().lower()`(先剥空格再转小写,顺序反过来也行)

6. `False`。优先级 not > and:先算 `not True` 得 False,再 `False and False` 得 False。

### 编程题 1:秒数换算器

编写 `seconds.py`:输入一个总秒数(整数),输出 `X 小时 Y 分钟 Z 秒`。
例:输入 7385,输出 `2 小时 3 分钟 5 秒`。
提示:1 小时 = 3600 秒;先用 `//` 取小时,再对余数继续拆。

**参考答案(homework/seconds.py):**

```python
# =============================================
# Day 02 作业 · 编程题 1:秒数换算器
# 考点:整除与取余的连环使用
# =============================================

total_seconds = int(input("请输入总秒数:"))

# 第一刀:总秒数里有几个 3600 秒 → 小时数
hours = total_seconds // 3600
# 余下的秒数(不足 1 小时的部分)
remainder = total_seconds % 3600

# 第二刀:余数里有几个 60 秒 → 分钟数
minutes = remainder // 60
# 再余下的就是秒
seconds = remainder % 60

print(f"{hours} 小时 {minutes} 分钟 {seconds} 秒")
```

验证:7385 // 3600 = 2,余 185;185 // 60 = 3,余 5 → `2 小时 3 分钟 5 秒`。✅

### 编程题 2:邮箱信息提取器 ★

编写 `email_parser.py`:输入一个邮箱地址(如 `zhang.san@deepseek.com`),程序输出:
① 用户名部分(@ 前);② 域名部分(@ 后);③ 该邮箱是否是公司邮箱(域名为 `deepseek.com` 则是);④ 脱敏邮箱:用户名只保留首字符,其余用 `***` 代替(如 `z***@deepseek.com`)。
提示:`split("@")` 一刀两断;比较域名前记得统一小写。

**参考答案(homework/email_parser.py):**

```python
# =============================================
# Day 02 作业 · 编程题 2:邮箱信息提取器
# 考点:split 拆分、索引取元素、字符串比较前先 lower、切片脱敏
# =============================================

COMPANY_DOMAIN = "deepseek.com"        # 公司域名做成常量,换公司只改这里

email = input("请输入邮箱地址:").strip()    # 进系统先清洗,养成条件反射

# split("@") 把邮箱一刀两断,得到 [用户名, 域名] 两段
parts = email.split("@")
username = parts[0]
domain = parts[1]

# 判断是否公司邮箱:比较前统一小写,避免 DeepSeek.COM 漏判
is_company = domain.lower() == COMPANY_DOMAIN

# 脱敏:用户名首字符 + *** + @ + 域名
masked = username[0] + "***@" + domain

print(f"用户名:{username}")
print(f"域名:{domain}")
print(f"公司邮箱:{is_company}")
print(f"脱敏显示:{masked}")
```

运行示例:输入 `zhang.san@DeepSeek.com`,输出用户名 `zhang.san`、域名 `DeepSeek.com`、公司邮箱 `True`、脱敏 `z***@DeepSeek.com`。
追问(不强制):如果用户输入里没有 @,`parts[1]` 会发生什么?(IndexError!怎么优雅处理?——明天的 if 判断,后天的作业里我们回收它。)

### 编程题 3:Prompt 模板填充器 ★

大模型开发中,Prompt 模板里常用 `{placeholder}` 占位。编写 `prompt_filler.py`:内置模板字符串(注意它是普通字符串,不是 f-string):

```python
template = "你是一名{role}。请用{tone}的语气,回答用户关于{topic}的问题,回答不超过{limit}字。"
```

依次询问用户 role、tone、topic、limit 四个值,用 **replace 方法**(不是 f-string!)把占位符逐个换成用户输入,输出最终 Prompt。
说明:真实框架(LangChain 的 PromptTemplate,Day 25)填充模板用的正是类似机制——模板先存起来,运行时才填值,f-string 做不到"先存后填",所以这题禁用 f-string,体会两者的本质区别。

**参考答案(homework/prompt_filler.py):**

```python
# =============================================
# Day 02 作业 · 编程题 3:Prompt 模板填充器
# 考点:replace 链式替换;理解"模板先存后填"与 f-string 的区别
# 伏笔:这就是 Day 25 LangChain PromptTemplate 的手工版
# =============================================

# 模板是普通字符串:{role} 等只是普通字符,没有 f 前缀就不会被立即求值。
# 这正是模板的价值:可以存在文件/数据库里,运行时才决定填什么
template = "你是一名{role}。请用{tone}的语气,回答用户关于{topic}的问题,回答不超过{limit}字。"

# 收集四个填充值(顺手清洗)
role = input("角色(如:资深法律顾问):").strip()
tone = input("语气(如:严谨专业):").strip()
topic = input("主题(如:劳动合同):").strip()
limit = input("字数上限(如:200):").strip()

# 链式 replace:每次替换返回新串,接力传递
prompt = (template
          .replace("{role}", role)
          .replace("{tone}", tone)
          .replace("{topic}", topic)
          .replace("{limit}", limit))
# (括号包住整个表达式后可以换行书写,长链式调用的规范排版)

print("-" * 40)
print("生成的 Prompt:")
print(prompt)
```

运行示例:输入"资深法律顾问 / 严谨专业 / 劳动合同 / 200",输出:
`你是一名资深法律顾问。请用严谨专业的语气,回答用户关于劳动合同的问题,回答不超过200字。`

## 第五部分:思考题(2 题)

**思考题 1:** 今天说"大模型应用开发 80% 的代码在处理字符串"。请列举你今天见过的至少 4 个"字符串方法 → 大模型场景"的对应关系。

**参考答案要点:**
- `strip().lower()` → 判断用户指令(/exit)、清洗用户输入;
- `split` / `join` → 文档清洗流水线的空格规范化(Day 28)、拆解 CSV 数据;
- `replace` → Prompt 模板填充(Day 25 的手工版)、敏感词打码(Day 57 安全合规);
- 切片脱敏 `[:3] + "****" + [-4:]` → 手机号/API Key 的日志脱敏;
- `in` / `count` → 检查模型输出是否含违禁内容(Day 18 防注入、Day 57 内容审核);
- `endswith` → 按扩展名路由文档解析器(Day 28);`startswith("/")` → 识别用户指令(Day 14)。
(写出任意 4 组、对应关系正确即可)

**思考题 2:** v4 清洗工具里,我们先做敏感词替换(F3)、后做空格规范化(F4)。如果把顺序反过来,结果会有区别吗?什么情况下流水线的工序顺序会影响结果?

**参考答案要点:** 对本例的测试数据,反转 F3/F4 顺序结果相同,因为敏感词内部没有空格。但一般而言**工序顺序是流水线设计的关键决策**:例如敏感词是"傻 子"(中间被人为插空格逃避检测),先做空格规范化把它并成"傻子"再替换才抓得住;再如先 lower 再比较域名,顺序反了就会漏判大写输入。设计流水线时要问:每道工序的输入假设是什么?前一道的输出是否满足它?——这个思维方式在 Day 28(先清洗再分割,顺序不能反)和 Day 33(先混合检索再重排,顺序不能反)会反复出现。
