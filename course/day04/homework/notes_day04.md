# Day 04 思考记录(参考范例)

## 思考题 1:对话历史无限增长会怎样?还有什么记忆策略?

后果:
1. 每次调 API 都要发送全部历史,token 费用随轮数线性上涨(Day 01 成本作业的延伸);
2. 超过模型上下文窗口上限(如 128K token)直接报错;
3. 输入越长响应越慢。

其他策略(Day 27 会正式全学到):
- **窗口记忆**:只保留最近 N 轮(编程题 3 实现的就是它的雏形);
- **摘要记忆**:把早期对话让大模型总结成一小段摘要,保"大意"弃"原文";
- **选择性保留**:固定保留 system 设定 + 最近几轮,中间压缩;
- **外部存储**:重要信息写进数据库/向量库,需要时检索回来——这个思路发展下去就是 RAG 和 Agent 长期记忆(Day 44)。

## 思考题 2:pop 与 append 之间崩溃会怎样?

后果:事项从待办消失却没进已完成——数据丢失。

这类问题叫**原子性**(atomicity):一组操作要么全做完,要么全不做。防御思路:
1. 调整顺序:先 append 后 pop,崩溃最多造成重复不会丢失("宁重勿丢");
2. 数据库的"事务"机制(Day 24 SQLite 的 commit/rollback);
3. 操作前记日志,崩溃后可恢复。
