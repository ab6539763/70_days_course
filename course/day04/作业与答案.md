A. 保存有序的对话历史

C. 保存 (x, y) 坐标
D. 保存需要按添加顺序展示的待办事项

### 选择题答案与解析

**1. B。** append 把 [4,5] 当"一个元素"塞进去,lst 变成 [1,2,3,[4,5]],长度 4。想变长度 5 用 extend。
**2. B。** `b = a` 是贴标签,两个名字一个列表,b.append 就是 a.append。想要独立副本:`b = a.copy()`。
**3. C。** sort 原地排序,返回 None。列表的原地方法(append/sort/reverse/clear)返回值全是 None,这是 Python 的刻意设计:提醒你"它没有产出新列表"。
**4. B。** enumerate 是"要编号"的标准答案;A 能跑但不地道;C、D 是语法错误的胡写。
**5. B。** range(4) 产出 0,1,2,3;if x>1 留下 2,3;乘 2 得 [4,6]。三个部件按"从哪来→什么条件→装什么"执行。
**6. B。** 逗号才是元组的本体,`(5)` 只是括号包着的整数 5。
**7. B。** `{}` 被空字典占用(明天正式认识),空集合唯一写法 `set()`。
**8. B。** `&` 是交集:两边都有的元素。
**9. C。** pop 删并"递给你";remove 按值删不递;del 按位置删不递;clear 全清。
**10. B。** 集合查"在不在"近乎瞬时,且违禁词天然无重复、不需要顺序。A、D 要有序用列表;C 定型数据用元组。

### 编程题 1:成绩单分析器

给定 `scores = [92, 45, 85, 58, 77, 63, 88, 51]`,输出:① 最高分、最低分、平均分(保留 1 位小数);② 及格名单(≥60,用推导式);③ 从高到低的成绩排名;④ 及格率。
提示:内置函数 `max(lst)`、`min(lst)`、`sum(lst)` 今天自学上岗,顾名思义。

**参考答案(homework/score_analyzer.py):**

```python
# =============================================
# Day 04 作业 · 编程题 1:成绩单分析器
# 考点:max/min/sum、推导式过滤、sorted、比率计算
# =============================================

scores = [92, 45, 85, 58, 77, 63, 88, 51]

# ① 三个统计:max/min/sum 是内置函数,接收列表直接出结果
highest = max(scores)
lowest = min(scores)
average = sum(scores) / len(scores)          # 平均 = 总和 / 个数

print(f"最高 {highest} | 最低 {lowest} | 平均 {average:.1f}")

# ② 及格名单:推导式过滤
passed = [s for s in scores if s >= 60]
print(f"及格名单:{passed}")

# ③ 排名:sorted 复制一份降序排(不动原始数据,保留"提交顺序")
ranking = sorted(scores, reverse=True)
print(f"排名:{ranking}")

# ④ 及格率:及格人数 / 总人数
rate = len(passed) / len(scores)
print(f"及格率:{rate:.1%}")
```

### 编程题 2:标签系统

模拟文章标签的合并与分析。给定两篇文章的标签列表(有重复):

```python
tags_a = ["python", "ai", "llm", "python", "rag"]
tags_b = ["ai", "agent", "llm", "docker"]
```

输出:① 两篇各自去重后的标签集合;② 共同标签;③ 只有 A 有的标签;④ 全部标签(并集)按字母序排列的列表。

**参考答案(homework/tag_system.py):**

```python
# =============================================
# Day 04 作业 · 编程题 2:标签系统
# 考点:set 去重 + 集合运算 + sorted 把集合变回有序列表
# =============================================

tags_a = ["python", "ai", "llm", "python", "rag"]
tags_b = ["ai", "agent", "llm", "docker"]

# ① 列表 → 集合:自动去重
set_a = set(tags_a)
set_b = set(tags_b)
print(f"A 去重:{set_a}")
print(f"B 去重:{set_b}")

# ② 交集:两篇共同话题
print(f"共同标签:{set_a & set_b}")

# ③ 差集:A 独有
print(f"A 独有:{set_a - set_b}")

# ④ 并集后排序:集合无序,展示给人看时用 sorted 变回有序列表
all_tags = sorted(set_a | set_b)
print(f"全部标签:{all_tags}")
```

### 编程题 3:模拟对话历史管理 ★★(Day 14 的直接预演)

用列表模拟 AI 对话历史管理,不用真的调 API。要求写一个循环程序:
① 用户每输入一句话,存入 `history` 列表,同时存入一条固定格式的模拟回复 `f"[AI回复] 收到:{用户输入}"`;
② 输入 `/history` 时,带编号打印全部记录;
③ 输入 `/count` 时,显示当前记录条数;
④ 当记录超过 6 条时,自动删除最早的 2 条并提示"记忆已压缩"(提示:切片 `history = history[2:]` 或两次 `pop(0)`);
⑤ `/exit` 退出。

**参考答案(homework/chat_history.py):**

```python
# =============================================
# Day 04 作业 · 编程题 3:模拟对话历史管理
# 考点:append 积累状态、切片截断、指令分发
# 这就是 Day 14 AI 助手的"记忆管理"裸奔版:
#   真实版只是把"模拟回复"换成 API 调用、把字符串换成字典(明天学)
# 第④点"超长截断"正是 Day 27 记忆窗口(window memory)的原始思想
# =============================================

history = []                       # 对话历史:程序的核心状态
MAX_LEN = 6                        # 记忆上限:常量

while True:
    text = input("你说:").strip()

    if not text:                   # 空输入:跳过(真值规则)
        continue

    if text == "/exit":
        print("再见!")
        break

    if text == "/history":
        if not history:
            print("(暂无记录)")
        for i, msg in enumerate(history, start=1):
            print(f"  {i}. {msg}")
        continue                   # 指令处理完,不落入"正常对话"分支

    if text == "/count":
        print(f"当前 {len(history)} 条记录")
        continue

    # ---- 正常对话:一问一答各存一条 ----
    history.append(f"[用户] {text}")
    history.append(f"[AI回复] 收到:{text}")
    print(f"[AI回复] 收到:{text}")

    # ---- 记忆压缩:超上限就砍掉最早的 2 条 ----
    if len(history) > MAX_LEN:
        history = history[2:]      # 切片:丢弃最早 2 条,留下其余
        print("(记忆已压缩:最早的一问一答被遗忘)")
```

### 编程题 4:购物车去重与结算

给定购物记录(重复代表多买):

```python
cart = ["苹果", "牛奶", "苹果", "面包", "牛奶", "苹果"]
prices = [("苹果", 5), ("牛奶", 12), ("面包", 8)]      # 元组列表:名字-单价
```

输出每种商品的购买数量和小计,以及总价。格式:`苹果 x3 = 15 元`。
提示:`cart.count(x)` 数数量;遍历 prices 时拆包 `for name, price in prices`。

**参考答案(homework/shopping_cart.py):**

```python
# =============================================
# Day 04 作业 · 编程题 4:购物车结算
# 考点:count 计数、元组拆包遍历、累加器
# 明天预告:prices 这种"名字→单价"的对应关系,字典才是它的真身
# =============================================

cart = ["苹果", "牛奶", "苹果", "面包", "牛奶", "苹果"]
prices = [("苹果", 5), ("牛奶", 12), ("面包", 8)]

total = 0                                  # 总价累加器

for name, price in prices:                 # 遍历元组列表,每轮拆包出名字和单价
    quantity = cart.count(name)            # 在购物记录里数这个商品出现几次
    subtotal = quantity * price
    total += subtotal
    print(f"{name} x{quantity} = {subtotal} 元")

print("-" * 20)
print(f"总计:{total} 元")
```

运行输出:苹果 x3 = 15 元 / 牛奶 x2 = 24 元 / 面包 x1 = 8 元 / 总计 47 元。
做完感受一下别扭之处:查"苹果的单价"居然要**遍历**整个 prices 列表。如果商品有 1 万种呢?——"按名字直接取值"的需求,正是明天字典的开场白。这题就是故意让你难受的。★

⑦ 功能 7"排序显示":按内容长度从短到长显示待办(不改变原列表顺序——用 sorted 别用 sort,想想为什么)。

**参考答案(homework/todo_v2.py 关键新增部分):**

```python
    # ---- 功能 6:修改 ----
    elif choice == "6":
        if not todos:
            print("没有待办可修改")
        else:
            num_text = input(f"修改第几项?(1-{len(todos)}):").strip()
```

## 第五部分:思考题(2 题)

**思考题 1:** 课件说"多轮对话的记忆,本质是一个不断被 append 的列表"。结合编程题 3 的"记忆压缩",思考:如果对话历史无限增长会发生什么?除了"砍掉最早的",你还能想到什么保留记忆的策略?

**参考答案要点:** 无限增长的后果:① 每次调 API 都要把全部历史发过去,token 费用随对话轮数线性上涨(Day 01 作业算过成本账);② 超过模型的上下文窗口上限(如 128K token)直接报错;③ 响应变慢。其他策略(Day 27 会全部正式学到):**摘要记忆**——把早期对话让大模型总结成一小段摘要,保留"大意"丢弃"原文";**选择性保留**——固定保留 system 设定和最近 N 轮,中间的压缩;**外部存储**——重要信息写进数据库/向量库,需要时检索回来(这个思路发展下去就是 RAG 和 Day 44 的 Agent 长期记忆)。能想到"总结压缩"或"存到外面需要再查"任一方向即优秀。

**思考题 2:** 待办管理器的功能 3(完成)用了"pop 出待办 + append 进已完成"两步。如果程序在 pop 之后、append 之前崩溃了,会发生什么?这类"两步操作中间不能断"的问题,你觉得工程上叫什么、怎么防?

**参考答案要点:** 后果:该事项从待办消失了,却没进已完成——**数据丢了**。这类问题工程上叫**原子性**(atomicity):一组操作要么全做完,要么全不做,不允许停在中间。防御思路:① 调整顺序,先 append 后 pop(崩溃最多造成重复,不会丢失——"宁重勿丢");② 真实数据库用"事务"(transaction)机制保证原子性,Day 24 学 SQLite 时会见到 commit/rollback;③ 操作前记日志,崩溃后可恢复。零基础第一周能意识到"两步之间会出事"就已经具备了工程直觉,答案方向对即满分。
