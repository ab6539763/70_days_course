## 1.1 创建列表与基本认知

列表:**有序、可变、可装任何类型**的容器。方括号定义,逗号分隔:

```python
# 创建列表的几种姿势
banned_words = ["赌博", "诈骗", "刷单"]          # 一批字符串
scores = [92, 85, 77, 60, 88]                   # 一批数字
mixed = ["张三", 28, 175.5, True]                # 混装也合法(但少用:类型统一才好批量处理)
empty = []                                       # 空列表:累积数据的起点(今天下午大量用)
chars = list("RAG")                              # list() 函数:把字符串拆成字符列表 ['R', 'A', 'G']

# 三个基本操作,全是老朋友:
print(len(scores))          # 5      len:元素个数(Day 02 的函数,通用于一切容器)
print(scores[0])            # 92     索引:从 0 开始(Day 02 的规则,原样适用)
print(scores[-1])           # 88     负索引:倒数
print(scores[1:3])          # [85, 77]  切片:含头不含尾,返回新列表
print(92 in scores)         # True   in:包含判断(Day 02 的运算符,原样适用)
```

注意到没有:**索引、切片、len、in,你一个新东西都不用学**——字符串上练的功夫全部平移过来。这就是 Python 的"序列协议":字符串、列表、元组共享同一套操作。Day 02 的苦练今天开始返利。

## 1.2 增:append / insert / extend

```python
todo = ["学列表", "写作业"]

todo.append("刷 LeetCode")
print(todo)                 # ['学列表', '写作业', '刷 LeetCode']

todo.insert(0, "复习昨天的循环")          # 插队到最前面

box2.extend([3, 4])         # extend 拆开逐个并入
```

## 1.3 删:remove / pop / clear / del

```python
todo = ["复习", "学列表", "写作业", "摸鱼", "提交 Git"]

# ── remove(值):按"值"删,删第一个匹配的 ──
todo.remove("摸鱼")
print(todo)                 # ['复习', '学列表', '写作业', '提交 Git']
# 值不存在会报 ValueError!删除前先用 in 检查是标准姿势:
if "摸鱼" in todo:
    todo.remove("摸鱼")

# ── pop(索引):按"位置"删,并把删掉的元素"递给你" ──
done = todo.pop(0)          # 删掉 0 号并接住它
print(f"已完成:{done}")     # 已完成:复习
print(todo)                 # ['学列表', '写作业', '提交 Git']
last = todo.pop()           # 不传参数:删最后一个(把列表当"栈"用,后进先出)
print(last)                 # 提交 Git

# ── clear():清空,留下空列表 ──
# todo.clear()              # []  ← Day 14 的 /clear 指令就是它!

# ── del 语句:按位置删,不递给你(还能删切片) ──
nums = [10, 20, 30, 40, 50]
del nums[0]
del nums[1:3]               # 删切片:一次删一段
print(nums)                 # [20, 50]
```

选择心法:**知道值用 remove,知道位置用 pop,还想要被删的东西也用 pop,全清用 clear**。

## 1.5 排序:sort / sorted / reverse

```python
scores = [92, 85, 77, 65, 88]

# ── 方式一:sort() —— 原地排序,列表自己变了,返回 None ──
scores.sort()
print(scores)               # [65, 77, 85, 88, 92]  升序
scores.sort(reverse=True)   # reverse=True:降序
print(scores)               # [92, 88, 85, 77, 65]

# ── 方式二:sorted(列表) —— 生成排好的新列表,原列表不动 ──
raw = [3, 1, 2]
ordered = sorted(raw)
print(raw, ordered)         # [3, 1, 2] [1, 2, 3]

# ⚠️ 两者混用的经典事故:
result = raw.sort()         # sort 原地干活,返回值是 None!
print(result)               # None  ← 不是排好的列表!
# 心法:sort 是"就地装修",sorted 是"复制一份再装修"
# 和 Day 02 的字符串方法对比着记:字符串方法全是"复制装修"(不可变嘛),
# 列表两种都提供,选哪种取决于你还要不要原始顺序

# ── reverse():原地反转(不排序,只倒序) ──
steps = ["加载", "分割", "向量化", "入库"]
steps.reverse()
print(steps)                # ['入库', '向量化', '分割', '加载']

# ── 排序的进阶:key 参数,按"加工后的值"排 ──
words = ["Agent", "rag", "Prompt", "llm"]
print(sorted(words))                        # ['Agent', 'Prompt', 'llm', 'rag'] 大写排前(按编码)
print(sorted(words, key=str.lower))         # ['Agent', 'llm', 'Prompt', 'rag'] 忽略大小写
print(sorted(words, key=len))               # ['rag', 'llm', 'Agent', 'Prompt'] 按长度
# key 的完整威力(按字典的某个字段排)明天讲完字典后解锁;
# Day 33 检索结果按相关性分数排序,用的正是 sorted(..., key=..., reverse=True)
```

## 1.6 可变性大坑:两个标签贴在同一个列表上(Day 01 伏笔总兑现)

Day 01 讲过:变量是**标签**,不是盒子。当时说"到 Day 04 这个模型能帮你避开大坑"。坑来了:

```python
a = [1, 2, 3]
b = a               # 把标签 b 也贴到 a 指向的那个列表上——没有复制!
b.append(4)         # 通过 b 修改列表
print(b)            # [1, 2, 3, 4]  意料之中
print(a)            # [1, 2, 3, 4]  ⚠️ a "也变了"!
```

初学者的惨叫:"我没动 a,a 怎么变了?!"——真相:**a 和 b 是同一个列表的两张标签,世界上从头到尾只有一个列表**。`b = a` 复制的是标签(引用),不是数据。字符串时代你没踩过这个坑,因为字符串不可变、想改只能造新的;列表可变,坑就露出来了。

想要真正的副本,明确说出来:

```python
a = [1, 2, 3]
b = a.copy()        # 复制数据:造一个内容相同的新列表(等价写法 b = a[:] 或 list(a))
b.append(4)
print(a)            # [1, 2, 3]     原列表安然无恙
print(b)            # [1, 2, 3, 4]

# 验证"是不是同一个"的照妖镜:id() 返回对象的身份证号
x = [1, 2]
y = x
z = x.copy()
print(id(x) == id(y))    # True   同一个对象
print(id(x) == id(z))    # False  两个对象
```

**这个坑的未来高发现场,先点名**:Day 06 函数把列表当参数传入(传的也是标签!函数内修改会影响外面);Day 14 想"备份对话历史再实验",不 copy 就会把正史改花。今天当堂踩过,将来就绕着走。

(嵌套列表的 copy 还有"浅拷贝"的细节——里层列表依然共享。今天知道有这回事即可,真踩到时排错手册见。)

## 1.7 遍历列表的三种姿势

```python
tasks = ["学列表", "写作业", "刷题"]

# 姿势一:直接遍历元素(昨天学的,最常用)
for task in tasks:
    print(task)

# 姿势二:enumerate —— 同时要"序号 + 元素"时的标准答案
for i, task in enumerate(tasks, start=1):     # start=1:序号从 1 起(默认 0)
    print(f"{i}. {task}")
# 输出:1. 学列表 / 2. 写作业 / 3. 刷题
# 【重点】今天下午待办管理器"显示编号列表"就靠它;
# 不要写 for i in range(len(tasks)) 再 tasks[i]——能跑,但不地道(non-Pythonic)

# 姿势三:zip —— 两个列表并排走
names = ["张三", "李四", "王五"]
scores = [92, 85, 77]
for name, score in zip(names, scores):
    print(f"{name}:{score} 分")
# zip 像拉链,把两条列表咬合成一对一对;长度不齐时以短的为准

# 顺带解锁:for 里的 "i, task" 和 "name, score" 是"拆包"语法——
# 一对值同时赋给两个变量。它就是 Day 02 那行 weight, height = 70, 1.75 的同族
```

**遍历时的铁律(昨天排错手册预告过)**:**不要边遍历边增删同一个列表**——元素会集体位移,导致跳过或重复处理。正确姿势是"遍历旧的,构建新的":

```python
nums = [1, 2, 3, 4, 5, 6]
# ❌ 危险:边遍历边 remove(结果诡异,自己试一次)
# ✅ 正确:造一个新列表装想留的
kept = []
for n in nums:
    if n % 2 == 0:
        kept.append(n)
print(kept)                 # [2, 4, 6]
```

而"遍历旧的,构建新的"这个模式,Python 给了它一个专属的优雅语法——下一节的主角。

# 上午 · 第二节(10:40 - 12:00):列表推导式 —— Python 的招牌菜

## 2.1 从三行到一行

刚才的"筛偶数"是三步舞:建空列表 → 遍历 → 条件 append。这个模式太高频,Python 把它压缩成一行:

```python
nums = [1, 2, 3, 4, 5, 6]

# 三行版(昨天的累加器模式)
kept = []
for n in nums:
    if n % 2 == 0:
        kept.append(n)

# 一行版:列表推导式(list comprehension)
kept = [n for n in nums if n % 2 == 0]
print(kept)                 # [2, 4, 6]
```

解剖推导式的语法,它就是三行版的"折叠":

```
kept = [ n            for n in nums      if n % 2 == 0 ]
         └─┬─┘        └─────┬─────┘      └─────┬──────┘
        ①装什么         ②从哪来           ③什么条件才要
       (append 的内容)  (for 那行)        (if 那行,可省略)
```

读法:"**从 nums 里取每个 n,满足偶数条件的,把 n 装进新列表**"。三个部件的顺序永远是:表达式 → for → if。

## 2.2 两种典型用法:过滤与加工

```python
# ── 用法一:过滤(if 部件出场)──
scores = [92, 45, 85, 58, 77]
passed = [s for s in scores if s >= 60]
print(passed)               # [92, 85, 77]

# ── 用法二:加工(表达式部件干活)──
words = ["  RAG ", " Agent", "Prompt  "]
cleaned = [w.strip().lower() for w in words]      # Day 02 清洗组合拳进了推导式
print(cleaned)              # ['rag', 'agent', 'prompt']

# ── 过滤 + 加工同时上 ──
raw = ["  张三 ", "", "  ", "李四", "王五  "]
names = [x.strip() for x in raw if x.strip()]     # 剥空格后非空的才要,且装进去的是剥过的
print(names)                # ['张三', '李四', '王五']
# 这一行是真实项目里"清洗用户数据"的标准写法,一个字都不多

# ── 配合 range:批量生成 ──
squares = [i ** 2 for i in range(1, 6)]
print(squares)              # [1, 4, 9, 16, 25]
```

## 2.3 使用尺度:一行流不是越多越好


# 下午 · 第一节(14:00 - 15:20):元组与集合

## 3.1 元组 tuple:焊死的列表

把方括号换成圆括号,列表就"焊死"了——**元组:有序、不可变**:

```python
# 创建
point = (3, 5)                       # 圆括号
rgb = (255, 128, 0)
single = (42,)                       # ⚠️ 单元素元组必须带逗号!(42) 只是括号包着的数字
also = 1, 2, 3                       # 圆括号其实可省略:逗号才是元组的本体

# 读操作与列表完全一致(序列协议再次生效)
print(point[0])           # 3
print(rgb[-1])            # 0
print(len(rgb))           # 3
print(255 in rgb)         # True

# 写操作全部禁止
# point[0] = 4            # TypeError: 'tuple' object does not support item assignment
# point.append(7)         # AttributeError:根本没有 append 方法
```

**既然功能是列表的子集,元组存在的意义是什么?** 三条,每条都实用:

1. **表达"这组数据是一个整体,不该被改"**:坐标 (x, y)、RGB 颜色、(纬度, 经度)。用元组是在向读代码的人**声明意图**:这仨是一体的,别动;
2. **能当字典的键**(明天见)——Day 02 说过"字典的键必须不可变",列表当键报错,元组可以;
3. **函数返回多个值的载体**(Day 06 见):`return name, age` 返回的其实是元组,接收时的 `name, age = ...` 就是今天上午见过的**拆包**。

拆包在元组上最常用,正式练一次:

```python
point = (3, 5)
x, y = point                 # 拆包:元组的元素按位置分给变量
print(x, y)                  # 3 5

# 变量交换的 Python 名场面(其他语言要借临时变量,Python 一行)
a, b = 1, 2
a, b = b, a                  # 右边先打包成元组 (2, 1),再拆给左边
print(a, b)                  # 2 1

# 昨天 endswith 传的 (".pdf", ".docx", ".md") 现在有名分了:就是元组
```

**心法:数据"生下来就定型"用元组,还要生长变化用列表。** 配置项、常量组合用元组;待办清单、对话历史用列表。

## 3.2 集合 set:自动去重的袋子

大括号定义(注意:**空集合必须用 `set()`**,`{}` 被字典占用了——明天你就知道为什么):

```python
# 集合:无序、不重复、元素必须不可变
tags = {"python", "ai", "python", "llm", "ai"}
print(tags)                  # {'python', 'llm', 'ai'}  重复的自动只留一份!顺序不保证

empty_set = set()            # 空集合的唯一正确写法
nums = set([1, 2, 2, 3, 3, 3])       # set() 函数:把列表转集合,顺手去重
print(nums)                  # {1, 2, 3}

# 增删
tags.add("rag")              # 加(不是 append——集合无序,没有"追加到末尾"的概念)
tags.discard("java")         # 删:不存在也不报错(remove 不存在会报 KeyError,首选 discard)
```

集合的两大绝活:

**绝活一:去重一行流。** 列表转集合再转回来:

```python
emails = ["a@x.com", "b@y.com", "a@x.com", "c@z.com", "b@y.com"]
unique = list(set(emails))
print(unique)                # 三个不重复的邮箱(顺序可能变!)

# 【伏笔兑现】Day 52 微调数据集清洗的"去重"工序,核心就是这一行——
```

## 4.3 代码实现(核心版)

```python
# =============================================
# 命令行待办事项管理器
# 需求编号:REQ-D04-001
# 架构:主循环 + 分发器(Day 03) + 双列表数据层(Day 04)
# 本项目是 Day 14《命令行 AI 助手》的结构预演
# =============================================

# ---- 数据层:两个核心列表,程序运行期间的全部"状态" ----
todos = []            # 待办事项
done_list = []        # 已完成事项

while True:
    # ---- 菜单 ----
    print()
    print("=" * 38)
    print(f"   待办管理器   待办 {len(todos)} 项 / 完成 {len(done_list)} 项")
    print("=" * 38)
    print("  1 查看  2 添加  3 完成  4 删除  5 统计  0 退出")
    choice = input("请选择:").strip()

    # ---- 功能 1:查看 ----
    if choice == "1":
        if not todos and not done_list:            # 真值规则:双空列表 = 什么都没有
            print("清单空空如也,用功能 2 添加第一件事吧!")
        if todos:
            print("【待办】")
            for i, task in enumerate(todos, start=1):     # enumerate:编号+内容一起来
                print(f"  {i}. {task}")
        if done_list:
            print("【已完成】")
            for task in done_list:
                print(f"  ✓ {task}")               # 已完成不需要编号(不再被操作)

    # ---- 功能 2:添加 ----
    elif choice == "2":
        task = input("输入待办内容:").strip()      # 清洗:老规矩
        if not task:                               # 拦空输入(真值规则)
            print("内容不能为空!")
        elif task in todos:                        # 拦重复(in 判断)
            print(f"「{task}」已在清单里了")
        else:
            todos.append(task)                     # 核心动作:append
            print(f"已添加:「{task}」")

    # ---- 功能 3:完成 ----
    elif choice == "3":
        if not todos:
            print("没有待办事项可完成")
        else:
            num_text = input(f"完成第几项?(1-{len(todos)}):").strip()
            # 编号校验:先 isdigit 防非数字,再范围防越界——Day 03 校验循环的精简版
            if not num_text.isdigit() or not (1 <= int(num_text) <= len(todos)):
                print("编号无效!")
            else:
                idx = int(num_text) - 1            # 用户看到的编号从 1 起,索引从 0 起:减 1 换算
                finished = todos.pop(idx)          # pop:从待办删掉并"递过来"
                done_list.append(finished)         # 接力 append 进已完成——一删一增完成"移动"
                print(f"完成:「{finished}」,漂亮!")

    # ---- 功能 4:删除(带二次确认)----
    elif choice == "4":
        if not todos:
            print("没有待办事项可删除")
        else:
            num_text = input(f"删除第几项?(1-{len(todos)}):").strip()
            if not num_text.isdigit() or not (1 <= int(num_text) <= len(todos)):
                print("编号无效!")
            else:
                idx = int(num_text) - 1
                # 二次确认:删除是不可逆操作,给用户反悔的机会(产品思维)
                confirm = input(f"确定删除「{todos[idx]}」?(y/n):").strip().lower()
                if confirm == "y":
                    removed = todos.pop(idx)
                    print(f"已删除:「{removed}」")
                else:
                    print("已取消")

    # ---- 功能 5:统计 ----
    elif choice == "5":
        total = len(todos) + len(done_list)
        if total == 0:
            print("暂无数据")
        else:
            rate = len(done_list) / total          # 完成率 = 已完成 / 总数
            print(f"待办 {len(todos)} | 已完成 {len(done_list)} | 完成率 {rate:.1%}")

    # ---- 退出 ----
    elif choice == "0":
        total = len(todos) + len(done_list)
        print(f"本次共管理 {total} 项事务,再见!")
        break

    else:
        print(f"没有选项 [{choice}]")
```

# 【常见错误与排错手册】Day 04 专属篇

**错误 1:`b = a` 以为是复制,改一个"两个都变"。** 本质:两张标签一个列表。要副本用 `b = a.copy()`。排查工具:`id(a) == id(b)` 为 True 就是同一个对象。

**错误 2:`result = my_list.sort()` 得到 None。** sort 原地干活不返回结果。要么 `my_list.sort()` 后直接用 my_list,要么 `result = sorted(my_list)`。同族错误:`append`、`reverse`、`clear` 的返回值全是 None,**列表的原地方法都不返回新列表**。

**错误 3:append 了一个列表,得到嵌套。** `box.append([3, 4])` 是塞进"一个元素"。要逐个并入用 `extend`,或 `box += [3, 4]`。

**错误 4:边遍历边 remove,结果跳着删。** 元素位移导致遍历指针错位。正确:推导式建新列表 `[x for x in lst if 要留的条件]`,或遍历副本 `for x in lst.copy():`。

**错误 5:`IndexError: list index out of range`。** 三大来源:空列表取 `[0]`;用户编号没减 1 就当索引(用户的"第 5 项"是索引 4!);循环边界 `range(len(lst) + 1)` 多跑一格。

**错误 6:单元素元组忘了逗号。** `(42)` 是整数 42,`(42,)` 才是元组。症状:后续 `for x in t:` 报 "'int' object is not iterable"。

**错误 7:`{}` 想创建空集合,实际得到空字典。** 空集合唯一写法 `set()`。症状:`.add()` 报 "'dict' object has no attribute 'add'"。

**错误 8:`remove` 不存在的值 / `index` 找不到的值 → ValueError。** 先 `in` 检查再操作;集合的 `discard` 不报错,可优先选用。

# 【课堂笔记】Day 04 知识点速查表

**列表 list:有序、可变、默认之选**
- 增:`append(x)` 尾追(90% 场景)| `insert(i, x)` 插队 | `extend(lst)` 并入
- 删:`remove(值)` | `pop(i)` 删并递给你(无参删尾)| `clear()` 清空 | `del lst[i]`
- 改:`lst[i] = 新值`(列表可变,字符串不行)
- 查:`in` | `index(值)` | `count(值)`
- 排:`lst.sort()` 原地返回 None | `sorted(lst)` 新列表 | `key=` 按加工值排 | `reverse=True` 降序
- 索引/切片/len/in:与字符串同一套(序列协议)

**可变性天坑**:`b = a` 是贴标签;副本要 `a.copy()`;函数传参同理(Day 06 见)

**遍历三姿势**:`for x in lst` | `enumerate(lst, start=1)` 要编号 | `zip(a, b)` 并排走
**铁律**:不边遍历边增删;"遍历旧的,构建新的"

**列表推导式**:`[表达式 for x in 序列 if 条件]`
- 过滤:`[s for s in scores if s >= 60]`
- 加工:`[w.strip().lower() for w in words]`
- 尺度:嵌套两层/一眼看不懂 → 改回多行 for

**元组 tuple:有序、不可变**
- `(1, 2)`;单元素 `(42,)` 逗号必须有;拆包 `x, y = point`;交换 `a, b = b, a`
- 场景:定型数据、字典的键、函数多返回值

**集合 set:无序、不重复**
- `{1, 2, 3}`;空集合 `set()`(`{}` 是字典!);`add / discard`
- 去重一行流:`list(set(lst))`(顺序会乱)
- 运算:`&` 交 `|` 并 `-` 差;查"在不在"比列表快得多
- 场景:去重(Day 52)、命中率计算(Day 34)、大表快查

**换算口诀**:用户编号 - 1 = 列表索引

# 【附录】课堂答疑实录(晚自习整理)

**问 1:什么时候用列表什么时候用元组,还是拿不准。**

答:一个字:**动不动**。这组数据在程序运行中会增删改吗?会 → 列表;生下来就定型 → 元组。再给一个偷懒版:**拿不准就用列表**,列表是万金油,用元组主要是"多一层保险 + 表达意图",初学阶段用错也不会出大事。真正必须元组的场景只有两个:当字典的键(明天)、习惯性的多返回值(Day 06)。

**问 2:`list(set(lst))` 去重后顺序乱了,怎么保序去重?**

答:两个方案。今天能懂的:建一个空列表,遍历原列表,"不在新列表里才 append"(in + append 的组合,自己写得出来);明天解锁的一行流:`list(dict.fromkeys(lst))`——利用字典键的两个特性:不重复 + 保持插入顺序。为什么字典的键保序?明天开场就讲。

**问 3:推导式和 for 循环性能有差别吗?**

答:推导式略快(内部是优化过的专用指令),但差距在数据百万级以下无感。选择依据永远是**可读性**,不是这点性能。真有性能焦虑时,瓶颈几乎总在别处(网络请求、模型推理),这是 Day 01 答疑"Python 慢不慢"的延伸:先让代码对,再让代码清楚,最后才谈快——而且要用测量说话(Day 46 讲 Agent 成本延迟优化时教你测)。

**问 4:集合为什么查得快?"算出位置"是什么意思?**

答:预告明天的哈希原理,先用类比:列表查东西像在没有目录的书里找一句话,只能一页页翻(挨个比对);集合像查新华字典——对要找的字先算拼音(哈希函数),直接翻到那一页。"算"的成本不随数据量增长,所以 10 万条数据里查一条,列表要比对 10 万次,集合算一次。代价:失去顺序(按拼音存放,不是按你放进去的顺序)。明天讲字典时会把哈希讲透,字典的键查得快是同一个原理。

**问 5:待办管理器为什么要两个列表?一个列表加个"已完成"标记不行吗?**

答:行,而且你说的方案更接近真实系统!用"一个列表 + 每项带状态字段"来建模,每项就得是 `{"task": "写作业", "done": False}` 这样的结构——这正是明天字典的开场需求(还记得下午"扎心的问题"吗)。今天用双列表是因为字典还没学,它是**当前知识约束下的合理设计**。明天学完字典,作业里就有"用字典重构待办管理器"。软件设计没有唯一正确答案,只有"当前约束下的合适"。

**问 6:enumerate 的 start=1 不写会怎样?**

答:序号从 0 开始。程序不报错,但用户看到"第 0 项"会懵——机器世界从 0 数,人类世界从 1 数,**展示给人看的编号要 start=1,拿去当索引用要减 1**。今天代码里 `idx = int(num_text) - 1` 就是这两个世界的换算口。这个换算忘了做,就是排错手册错误 5 的 IndexError。

**问 7:`todos.pop(idx)` 和 `del todos[idx]` 都能删,选哪个?**

答:看你要不要"尸体"。pop 删完把元素递给你(我们要打印"完成了什么",所以用 pop 接住);del 删完就没了(纯删除、不需要知道删了啥的场合)。功能 3 移动事项必须 pop(要拿到内容才能 append 到已完成);功能 4 其实 del 也行,但代码里还是用了 pop——为了打印"已删除:xxx"给用户确认感。细节处见产品心。

**问 8:今天说列表是"状态",这个词什么意思?**

答:状态(state)= 程序在某一时刻"记住的所有数据"。待办管理器的状态就是两个列表的内容;它随操作不断变化,决定了程序下一步的行为(清单空不空,菜单功能的反应就不同)。这个词今后会高频出现:Day 27 的对话记忆是状态、Day 41 LangGraph 的核心概念就叫 State、Day 42 的"持久化 Checkpointer"就是把状态存盘。从今天起,看到程序先问"它的状态是什么、存在哪",你就有了架构师的第一视角。
