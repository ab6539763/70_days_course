### 选择题答案与解析

**1. C。** 方括号取不存在的键直接 KeyError。这是特性不是缺陷:必要字段缺失就该响亮地崩。
**2. B。** get 的第二个参数是"缺键时的默认值"。可选字段的标准姿势。
**3. C。** 键必须不可变:元组可以;列表、字典、集合都是可变类型,unhashable。
**4. C。** items() 产出键值对,配合拆包 `k, v` 一次拿两个。直接 `for k, v in d` 会 ValueError。
**5. B。** JSON 布尔全小写不带引号。带引号的 `"true"` 是字符串不是布尔——这个坑在解析后判断 `if data["vip"] == True` 时会现形。
**6. C。** null 是 JSON 合法空值。A 单引号、B 尾逗号、D 注释,均非法——JSONDecodeError 三大来源 + 注释。
**7. B。** loads = load string,把字符串解析成对象。方向口诀:**解析进来(loads),序列化出去(dumps)**。
**8. B。** ensure_ascii=False 关闭"非 ASCII 字符转义",中文才能原样输出。
**9. B。** choices 是**列表**,必须先 `[0]` 取第一个元素再往里走。剥洋葱口诀:每层先问是字典还是列表。这就是"第一名句"。
**10. C。** system 设定人设规则,user 是用户发言,assistant 是模型回答。

### 编程题 1:购物车终极版(还昨天的账)

用字典重做昨天的购物车:`prices = {"苹果": 5, "牛奶": 12, "面包": 8}`,购物记录仍是 `cart = ["苹果", "牛奶", "苹果", "面包", "牛奶", "苹果"]`。要求:① 用一个字典 `counter` 统计每种商品的购买数量(不许用 count 方法,用遍历 + 字典累加——这是"字典计数器"模式,必练);② 输出每种商品的小计和总价;③ 尝试结算一个价格表里没有的商品 "榴莲",程序要给出"暂无价格"而不是崩溃。

**参考答案(homework/cart_dict.py):**

```python
# =============================================
# Day 05 作业 · 编程题 1:购物车终极版
# 考点:字典计数器模式(重中之重)、get 防御、items 遍历
# =============================================

prices = {"苹果": 5, "牛奶": 12, "面包": 8}
cart = ["苹果", "牛奶", "苹果", "面包", "牛奶", "苹果", "榴莲"]   # 混入一个没价格的

# ---- ① 字典计数器模式:遍历 + get 累加 ----
# 逻辑:每见到一个商品,把它在 counter 里的计数 +1;
#       第一次见到时 counter 里还没有它,get 的默认值 0 兜底
counter = {}
for item in cart:
    counter[item] = counter.get(item, 0) + 1
print(counter)          # {'苹果': 3, '牛奶': 2, '面包': 1, '榴莲': 1}
# 这个三行模式请背下来:词频统计(Day 11)、投票计数,全是它

# ---- ② 结算:遍历计数器,查价格表 ----
total = 0
for item, qty in counter.items():
    if item not in prices:                 # ③ 防御:价格表里没有的商品
        print(f"{item} x{qty}:暂无价格,跳过")
        continue
    subtotal = prices[item] * qty          # 有价格:方括号放心取
    total += subtotal
    print(f"{item} x{qty} = {subtotal} 元")

print("-" * 20)
print(f"总计:{total} 元")
```

对比昨天:查价格从"遍历比对"变成"一步直取",数量统计从 count 变成通用的计数器模式。**字典计数器 `d[k] = d.get(k, 0) + 1` 是本周必须焊死的三行之一。**

### 编程题 2:待办管理器数据层重构 ★(兑现昨天的扎心问题)

把待办事项升级成字典结构:每条待办为 `{"task": 内容, "priority": "高/中/低", "done": False}`,整体是字典列表。实现一个精简版管理器(不用完整菜单,顺序执行即可):① 添加三条不同优先级的待办;② 打印全部(格式:`□ [高] 复习JSON`,完成的用 ✓);③ 把第 1 条标记为完成(改 done 字段,**不再需要两个列表了!**);④ 用推导式取出"未完成"子清单;⑤ 按优先级排序打印(高→中→低)。

**参考答案(homework/todo_dict.py):**

```python
# =============================================
# Day 05 作业 · 编程题 2:待办数据层重构
# 考点:字典列表建模、改字段代替移动列表、推导式过滤、权重排序
# 对比 Day 04:两个列表(todos/done_list)合并成一个字典列表,
#            "完成"从"pop+append 移动"简化为"改一个布尔字段"——
#            数据结构选对了,代码自然变简单
# =============================================

# ① 添加三条(真实程序里是 append,这里直接字面量初始化)
todos = [
    {"task": "复习JSON", "priority": "高", "done": False},
    {"task": "写作业", "priority": "中", "done": False},
    {"task": "刷LeetCode", "priority": "低", "done": False},
]

# ② 打印全部
def show(items):                      # 偷跑一个函数(明天正式学),避免打印逻辑抄三遍
    for i, t in enumerate(items, start=1):
        mark = "✓" if t["done"] else "□"
        print(f"  {i}. {mark} [{t['priority']}] {t['task']}")

print("全部待办:")
show(todos)

# ③ 完成第 1 条:改字段,不用移动
todos[0]["done"] = True
print("完成第 1 条后:")
show(todos)

# ④ 未完成子清单:推导式过滤
pending = [t for t in todos if not t["done"]]
print("未完成:")
show(pending)

# ⑤ 按优先级排序:字典定义权重 + sorted key
order = {"高": 0, "中": 1, "低": 2}
by_priority = sorted(todos, key=lambda t: order[t["priority"]])
print("按优先级:")
show(by_priority)
```

# =============================================
# Day 05 作业 · 编程题 3:messages 工具箱
# 考点:messages 结构的组装、遍历、映射、统计
# 这些零件将在 Day 14 项目一里原样上岗

# ① 初始化:system 打底

total_count = len(messages)

char_count = sum(len(m["content"]) for m in messages)   # 生成器写法,与推导式同族

### 编程题 4:JSON 修复诊所

下面五个字符串,有的能被 json.loads 解析,有的不能。先人肉判断每个是否合法、错在哪,再写程序逐个尝试解析验证(用课上见过的 try/except 形式照抄即可):

```python
samples = [
    '{"a": 1, "b": 2}',
    "{'a': 1}",
    '{"a": true, "b": null}',
    '{"a": 1,}',
    '{"a": "他说:\\"你好\\""}',
]
```

**参考答案(homework/json_clinic.py):**

```python
# =============================================
# Day 05 作业 · 编程题 4:JSON 修复诊所
# 考点:JSON 语法规则的手感 + 用程序验证人肉判断
# =============================================
import json

samples = [
    '{"a": 1, "b": 2}',              # ✅ 合法
    "{'a': 1}",                      # ❌ 单引号
    '{"a": true, "b": null}',        # ✅ 合法:小写 true/null 正是 JSON 规范
    '{"a": 1,}',                     # ❌ 尾逗号
    '{"a": "他说:\\"你好\\""}',      # ✅ 合法:字符串内部的双引号用 \" 转义
]

for i, s in enumerate(samples, start=1):
    try:
        data = json.loads(s)
        print(f"样本{i}:✅ 合法 → {data}")
    except json.JSONDecodeError as e:
        print(f"样本{i}:❌ 非法 → {e}")
```

人肉判断答案:1 合法;2 非法(单引号);3 合法(小写 true/null 正是规范写法,别被 Python 习惯带偏);4 非法(尾逗号);5 合法(`\"` 是字符串内嵌双引号的转义写法——Day 02 转义字符的复利)。

### 编程题 5:模型价格查询器

内置价格表(字典嵌套字典):

```python
PRICE_TABLE = {
    "deepseek-chat": {"input": 1.0, "output": 4.0},
    "gpt-4o": {"input": 18.0, "output": 72.0},
    "qwen-plus": {"input": 4.0, "output": 12.0},
}
```

写一个循环程序:用户输入模型名 → 查表输出两项价格;模型不存在时列出全部可选模型名;输入 /exit 退出。加分项:再输入预计的输入/输出 token 数,算出预估成本。

**参考答案(homework/price_lookup.py):**

```python
# =============================================
# Day 05 作业 · 编程题 5:模型价格查询器
# 考点:嵌套字典查询、in 防御、keys 列举、主循环骨架(Day 03 复利)
# =============================================

PRICE_TABLE = {
    "deepseek-chat": {"input": 1.0, "output": 4.0},
    "gpt-4o": {"input": 18.0, "output": 72.0},
    "qwen-plus": {"input": 4.0, "output": 12.0},
}

while True:
    name = input("模型名(/exit 退出):").strip().lower()    # 清洗+统一小写

    if name == "/exit":
        print("再见!")
        break

    if name not in PRICE_TABLE:                    # in 查键:防 KeyError
        # ", ".join(...) 把所有键拼成人话(Day 02 join 的复利)
        print(f"没有 [{name}],可选:{', '.join(PRICE_TABLE.keys())}")
        continue

    price = PRICE_TABLE[name]                      # 确认存在后,方括号放心取
    print(f"{name}:输入 {price['input']} 元/百万 | 输出 {price['output']} 元/百万")

    # ---- 加分项:成本预估 ----
    t_in = input("预计输入token数(回车跳过):").strip()
    if t_in.isdigit():
        t_out = input("预计输出token数:").strip()
        if t_out.isdigit():
            cost = (int(t_in) / 1_000_000 * price["input"]
                    + int(t_out) / 1_000_000 * price["output"])
            print(f"预估成本:{cost:.4f} 元")
```

## 第五部分:思考题(2 题)

**思考题 1:** LeetCode 第 1 题"两数之和",昨天你可能用了双层循环(对每个数,再遍历找配对)。今天要求用字典重做:遍历一次,每个数先问"我需要的搭档(target - 当前数)在字典里吗?",不在就把自己存进字典(值为下标)。请说明:为什么字典版更快?快在哪一步?

**参考答案要点:** 双层循环:外层 n 次 × 内层平均 n/2 次 ≈ n² 级比对(1 万个数就是约 5 千万次)。字典版:遍历一次 n 步,每步"查搭档在不在"是哈希直取(一步),总共 n 级。快就快在**"挨个找搭档"被"算出搭档的位置"替代**——哈希把查找从线性降为常数。这就是今天 1.6 节哈希原理的第一次实战变现,也是"选对数据结构 = 换一个数量级的性能"的经典案例。

**思考题 2:** 今天说"让大模型输出 JSON,结果它输出得不标准"是真实工作里 JSONDecodeError 的主要来源。猜一猜:模型输出的 JSON 通常会怎么"不标准"?如果你是工程师,收到一段"疑似 JSON"的模型输出,你会怎么处理?

**参考答案要点:** 常见不标准形态:① 前后夹带解释文字("好的,以下是JSON:{...} 希望对你有帮助");② 用 Markdown 代码块包裹(```json ... ```);③ 尾逗号、单引号、没转义的内嵌引号;④ 干脆输出了不完整的半截 JSON(被 max_tokens 截断,finish_reason=length)。工程处理思路:① Prompt 里严格约束"只输出 JSON,不要任何其他文字"(Day 17/18);② 解析前先"掏"——用字符串方法或正则把 `{...}` 部分抠出来(find("{") 与 rfind("}") 切片,今天的技能!);③ try/except 包住 loads,失败就重试或让模型自己修(Day 18);④ 用 API 的 JSON Mode / Function Calling 从根上保证格式(Day 18/19)。能想到"约束 + 提取 + 容错"任意两个方向即优秀。
