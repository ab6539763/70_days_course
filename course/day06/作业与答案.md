**7. B。** key 参数接收一个函数,sorted 对每个元素调用它、按返回值排序。lambda 在此表达"按长度"这条规则。
**8. B。** 注册表存函数**本身**(不带括号);带括号是立刻执行,存进去的是执行结果(往往是 None)。
**9. B。** 缺出口 = 无限递归 → RecursionError;规模不缩小同理。
**10. B。** print 把结果焊死在"命令行展示"这一种用途上;return 让调用方自由决定用途——这是复用性的关键。

### 读程序题答案与解析

**1.**
```

```

**2.**
```

```

**3.**
```

```

**4.**
```

```

### 编程题 1:BMI 终于不用复制粘贴了(还 Day 03 的账)

把 Day 03 作业 bmi_v2.py 里两段几乎一样的校验循环,重构成一个函数 `read_positive_float(prompt: str) -> float`,调用两次。分级逻辑也提取成 `bmi_level(bmi: float) -> str`。主流程放进 `main()`。

**参考答案(homework/bmi_v3.py):**

```python
# =============================================
# Day 06 作业 · 编程题 1:BMI 3.0(函数化重构)
# 对比 Day 03 版:两段校验循环 → 一个函数调两次(DRY 落地)
# =============================================

def read_positive_float(prompt: str) -> float:
    """读取一个正的小数,不合法就重问,保证返回合法值。"""
    while True:
        text = input(prompt).strip()
        # 删掉第一个小数点后全是数字,且值为正 → 合法
        if text.replace(".", "", 1).isdigit() and float(text) > 0:
            return text and float(text)      # return 兼职 break
        print("请输入正数!")


def bmi_level(bmi: float) -> str:
    """BMI 分级:纯函数,只 return 不 print,可独立测试。"""
    if bmi >= 28:
        return "肥胖"
    if bmi >= 24:
        return "偏胖"
    if bmi >= 18.5:
        return "正常"
    return "偏瘦"


def main() -> None:
    """主流程:输入 → 计算 → 输出。"""
    weight = read_positive_float("体重(公斤):")
    height = read_positive_float("身高(米,如 1.75):")
    bmi = weight / (height ** 2)             # 幂运算替代 height*height
    print(f"BMI = {bmi:.1f},分级:{bmi_level(bmi)}")

    # 纯函数的红利:一行 assert 就是一个测试
    assert bmi_level(22.0) == "正常"
    assert bmi_level(28.0) == "肥胖"


if __name__ == "__main__":
    main()
```

(注意:上面 `return text and float(text)` 是一处刻意留错的干扰写法吗?不是——它利用了 and 的短路求值,text 非空时返回 float(text)。但这种"聪明"写法可读性差,**更推荐直白的 `return float(text)`**,参考代码文件里用的是直白版。发现并质疑这行的同学,奖励一朵小红花:读参考答案也要带脑子。)

### 编程题 2:消息工厂 ★(Day 14 零件二次加工)

基于 Day 05 作业的 messages 工具箱,函数化为四个纯函数:
`make_message(role, content)` 造一条消息;`add_user_message(messages, content)` 与 `add_assistant_message(messages, content)` 追加消息(原地修改,动词命名明示);`format_history(messages) -> str` 把整段历史格式化成带角色标签的多行字符串(**return 字符串,不 print**)。写 main() 演示三轮对话并打印。

**参考答案(homework/message_factory.py):**

```python
# =============================================
# Day 06 作业 · 编程题 2:消息工厂
# 考点:纯函数 + 原地修改函数的命名约定 + 展示与逻辑分离
# 这四个函数将在 Day 14 项目一里几乎原样上岗
# =============================================

ROLE_NAMES = {"system": "[系统]", "user": "[我]", "assistant": "[AI]"}   # 模块级常量


def make_message(role: str, content: str) -> dict:
    """构造一条标准消息字典。"""
    return {"role": role, "content": content}


def add_user_message(messages: list, content: str) -> None:
    """追加一条用户消息(原地修改 messages)。"""
    messages.append(make_message("user", content))      # 函数复用函数


def add_assistant_message(messages: list, content: str) -> None:
    """追加一条 AI 消息(原地修改 messages)。"""
    messages.append(make_message("assistant", content))


def format_history(messages: list) -> str:
    """把对话历史格式化为多行字符串。只 return 不 print。"""
    lines = [f"{ROLE_NAMES.get(m['role'], '[?]')} {m['content']}" for m in messages]
    return "\n".join(lines)                              # join:Day 02 复利


def main() -> None:
    messages = [make_message("system", "你是Python学习助教")]
    for q in ["什么是函数?", "return和print区别?", "什么是纯函数?"]:
        add_user_message(messages, q)
        add_assistant_message(messages, f"关于「{q}」的解答是……")
    print(format_history(messages))                      # 打印权在调用方
    print(f"\n共 {len(messages)} 条消息")


if __name__ == "__main__":
    main()
```

### 编程题 3:成绩工具集(*args 实战)

实现三个函数并测试:`stats(*scores) -> dict` 返回 `{"max":…, "min":…, "avg":…}`(空参数返回全 0 的字典);`top_n(scores: list, n: int = 3) -> list` 返回前 n 高的成绩(不修改原列表!);`pass_rate(scores: list, line: int = 60) -> float` 及格率。每个函数配至少一条 assert 测试。

**参考答案(homework/score_tools.py):**

```python
# =============================================
# Day 06 作业 · 编程题 3:成绩工具集
# 考点:*args、默认参数、sorted 不动原列表、assert 自测
# =============================================

def stats(*scores) -> dict:
    """任意个成绩的统计:最高/最低/平均。"""
    if not scores:                                # 防空:*args 收到空元组
        return {"max": 0, "min": 0, "avg": 0}
    return {
        "max": max(scores),
        "min": min(scores),
        "avg": sum(scores) / len(scores),
    }


def top_n(scores: list, n: int = 3) -> list:
    """前 n 高的成绩。用 sorted(不是 sort):绝不修改调用方的原列表。"""
    return sorted(scores, reverse=True)[:n]      # 降序排 + 切片取前 n


def pass_rate(scores: list, line: int = 60) -> float:
    """及格率(0~1)。分数线可调,默认 60。"""
    if not scores:
        return 0.0
    passed = [s for s in scores if s >= line]
    return len(passed) / len(scores)


def main() -> None:
    data = [92, 45, 85, 58, 77, 63]

    print(stats(*data))                          # 列表 * 解包成位置参数——*args 的反向
    print(top_n(data))                           # 默认前 3
    print(top_n(data, n=2))                      # 关键字参数覆盖
    print(f"{pass_rate(data):.1%}")

    # ---- assert 自测:纯函数的红利 ----
    assert stats(90, 80)["avg"] == 85
    assert stats() == {"max": 0, "min": 0, "avg": 0}
    assert top_n([3, 1, 2], n=2) == [3, 2]
    assert pass_rate([60, 59]) == 0.5
    original = [3, 1, 2]
    top_n(original)
    assert original == [3, 1, 2]                 # 验证原列表未被修改!
    print("✓ 全部测试通过")


if __name__ == "__main__":
    main()
```

工具层:`find_by_index(todos, num) -> dict | None`(用户编号转待办项,越界返回 None);功能层:`show_todos(todos)`、`add_todo(todos)`、`finish_todo(todos)`;入口层:`main()` 字典驱动菜单。要求全部规范落实(docstring、注解、注册表)。

**参考答案(homework/todo_functional.py)**:见代码文件,结构与课堂 toolbox.py 一致。关键片段:

```python
def find_by_index(todos: list, num_text: str) -> dict | None:
    """把用户输入的编号转成待办项字典;非法或越界返回 None。

    dict | None 的写法表示"返回字典或 None"(Python 3.10+),
    调用方必须处理 None——把"可能失败"写进类型里。
    """
    if not num_text.isdigit():
        return None
    idx = int(num_text) - 1                    # 人类编号 → 索引
    if not (0 <= idx < len(todos)):
        return None
    return todos[idx]
```

## 第五部分:思考题(2 题)

**思考题 1:** 读程序题 3 里,`outer` 返回的 `inner` 函数"记住了"制造它时的 n(double 记住 2,triple 记住 3)。按 2.1 节的作用域规则,outer 执行完局部变量应该销毁,n 为什么还活着?大胆猜一个解释,并想想这个能力可能有什么用。

**参考答案要点:** 这个现象叫**闭包(closure)**:内层函数引用了外层的变量时,Python 会让这些变量"跟着内层函数走"(打包进函数对象里),外层结束也不销毁。直觉解释:inner 出生时带走了"出生环境的快照"。用处:① 制造"预设了配置的专用函数"(编程题 5 的 lambda 打包同理);② **装饰器的地基**——Day 13 的 @retry 之所以能给任意函数加重试,就是闭包让"包装函数"记住了"被包装的函数"。答出"变量被内层函数带走了"的直觉即满分,术语不要求。

**思考题 2:** 公司规范要求"工具函数只 return 不 print",但 `run_guess` 这样的功能层函数里一堆 print。这算违反规范吗?说说你对"分层"里每层职责的理解。

**参考答案要点:** 不违反。规范约束的是**工具层**(纯逻辑,谁都可能复用,print 会污染复用场景);**功能层的职责恰恰就是交互**(收输入、给反馈),print 是它的本职工作。分层的本质是**职责分配**:工具层管"算得对",功能层管"聊得好",入口层管"调度得清楚"。判断代码该放哪层,就问"它在干哪类活"。延伸:Day 23 的 Web 项目里,功能层的 print 会被替换成"返回 JSON 响应"——因为交互对象从终端用户变成了前端程序,但三层的职责划分原样保留。
