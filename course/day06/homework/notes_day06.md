# Day 06 思考记录(参考范例)

## 思考题 1:inner 为什么记得 n?(闭包)

现象:outer 执行完,局部变量本应销毁,但 double(5) 依然算出 10——inner 记得制造它时的 n=2。

解释:这叫**闭包(closure)**。内层函数引用了外层变量时,Python 把这些变量"打包进内层函数对象"一起带走——inner 出生时带走了出生环境的快照。

用处:
1. 制造"预设了配置的专用函数"(menu_lambda.py 的 lambda 打包同理);
2. **装饰器的地基**(Day 13):@retry 能给任意函数加重试,靠的就是闭包让"包装函数"记住"被包装的函数"。

## 思考题 2:功能层的 print 违反"只 return 不 print"吗?

不违反。规范约束的是**工具层**:纯逻辑、可能被任何场合复用,print 会污染复用场景。**功能层的本职就是交互**,print 是它的正当工作。

分层 = 职责分配:
- 工具层:算得对(纯函数,可测试);
- 功能层:聊得好(交互与展示);
- 入口层:调度得清楚(菜单/路由)。

延伸:Day 23 的 Web 项目里,功能层的 print 会换成"返回 JSON 响应"——交互对象从终端用户变成前端程序,但三层职责划分原样保留。
