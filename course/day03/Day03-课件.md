# 上午 · 第一节(9:00 - 10:30):if / elif / else 条件判断

## 1.1 从一个真实需求进入:年龄校验

直接兑现 Day 01 的思考题。当时的问题:年龄输入 `-5` 或 `200`,程序不报错但结果荒谬。现在有了 if,三行解决:

```python
age = int(input("请输入你的年龄:"))

if age < 0 or age > 120:
    print("年龄不合法,请检查输入!")
```

逐个部位解剖这个新语法:

```
if age < 0 or age > 120:
│  └──────┬──────────┘│
│      条件表达式      │
│  (昨天学的,产出     └── 冒号:必须有!表示"条件说完了,下面是要做的事"
│   True/False)
└── if 关键字:"如果"

    print("年龄不合法,请检查输入!")
└┬─┘
 └── 缩进:4 个空格。缩进的行属于 if 管辖——条件为 True 才执行
```

两个语法要点,**每个都是今天的高频报错点**:

**要点 1:冒号。** if 那行末尾必须有英文冒号 `:`。忘写冒号 → `SyntaxError: expected ':'`。Python 里"冒号 + 缩进"是固定搭档:凡是"下面有一块附属代码"的语句(今天的 if/while/for,以后的 def/class),行尾都有冒号。

**要点 2:缩进(Python 的灵魂设定)。** 其他语言用大括号 `{}` 圈定代码块,Python 用**缩进**——挪进去 4 个空格,就表示"这行归上面的 if 管"。缩进不是美观问题,是**语法本身**:

```python
score = 85

if score >= 60:
    print("及格了")        # 缩进 4 格:归 if 管,条件为 True 才执行
    print("继续保持")      # 同样缩进:也归 if 管
print("程序结束")          # 没缩进:不归 if 管,无论如何都执行
```

约定:**一律用 4 个空格**。好消息是 VS Code 里按 Tab 键会自动转成 4 个空格,回车后也会自动保持缩进,你只需要在"这块结束了"的时候按退格键跳出来。坏消息是初学者常犯两种缩进错:该缩没缩(`IndentationError: expected an indented block`)、缩得深浅不一(`IndentationError: unexpected indent`)。排错手册见文末。

## 1.3 elif:多路分支

超过两条岔路时,用 `elif`(else if 的缩写)串联:

```python
# 场景:根据分数定等级
score = int(input("请输入分数(0-100):"))

if score >= 90:
    grade = "优秀"
elif score >= 80:          # 走到这里,隐含"score < 90"已经成立
    grade = "良好"
elif score >= 60:          # 走到这里,隐含"score < 80"
    grade = "及格"
else:                      # 以上全不成立:score < 60
    grade = "不及格"

print(f"分数 {score},等级:{grade}")
```

**elif 的执行逻辑必须刻进脑子:从上到下逐个检查,命中一个就执行并退出整个结构,后面的看都不看。** 所以第二个条件写 `score >= 80` 就够了,不用写 `80 <= score < 90`——能走到第二关,说明第一关(>=90)已经没通过,`score < 90` 是白送的。

这个特性带来一个经典陷阱:**顺序错了,逻辑就错了**:

```python
# 反面教材:条件顺序写反
if score >= 60:
    grade = "及格"          # 95 分会在这里被拦截,得到"及格"!
elif score >= 90:
    grade = "优秀"          # 永远走不到:能到这里的一定 < 60,不可能 >= 90
```

这段代码不报错,95 分被判成"及格"——又是"不报错的逻辑错误"。守则:**多路分支的条件,按从严到宽(或从宽到严)的单调顺序排列,不要乱序。**

# 上午 · 第二节(10:40 - 12:00):while 与 for 循环

## 2.1 while:不达目的不罢休

while 的结构和 if 长得一模一样,区别在行为:**if 判断一次,while 判断完执行、执行完再回去判断,直到条件变 False**:

```python
# 数数:1 到 5
count = 1                    # ① 初始化:循环变量起点
while count <= 5:            # ② 条件:True 就进循环体,False 就离开
    print(f"第 {count} 次")
    count += 1               # ③ 更新:昨天的复合赋值,推动循环走向终点
print("循环结束")
```

while 循环的三要素:**初始化、条件、更新**。三者缺一,通常就是两种事故:忘了初始化 → NameError;忘了更新 → **死循环**(条件永远 True,程序永不停止)。现场体验一次死循环是今天的必修课:把 `count += 1` 注释掉运行,终端会疯狂刷屏——**按 `Ctrl + C` 强制终止**,这个快捷键是程序员的急刹车,今天必须练一次,以后救急全靠它。

## 2.2 `while True` + break:故意的死循环

死循环也有正用:**故意让条件永远为真,在循环体内部用 `break` 找出口**。这是交互程序的标准骨架:

```python
# 复读机:你说什么它说什么,说"再见"才退出
while True:                            # 故意的死循环:程序一直待命
    text = input("你说:").strip()

    if text == "再见":
        print("再见!")
        break                          # break:立刻砸破循环,跳到循环后面

    print(f"复读机:{text}")

print("程序已退出")
```

请盯着这个骨架看十秒钟,记住它的形状:**`while True` → 收输入 → if 判断特殊指令就 break → 否则正常处理**。三十秒后你会在下午的菜单系统里重写它,11 天后你会在 Day 14 的 AI 助手里第三次写它——那时"正常处理"那一行,换成了"发给大模型 API"。骨架从今天起就没变过。

`break` 的兄弟 `continue`:不砸循环,只**跳过本轮剩余代码,直接进下一轮**:

```python
# 只处理有效输入:空输入跳过,不计入次数
count = 0
while count < 3:
    text = input("请输入关键词:").strip()
    if not text:               # 真值规则:空字符串为 False,not 一下变 True
        print("输入为空,请重新输入")
        continue               # 跳过下面的 count += 1,重新要求输入
    print(f"已记录:{text}")
    count += 1
```

break 和 continue 的一句话区分:**break 是"不玩了",continue 是"这把不算,再来"**。

## 2.3 输入校验循环:三天伏笔的总兑现

Day 01 思考题 2 的完整答案,现在可以写出来了——"校验失败就重新输入,直到合法为止":

```python
# 输入校验循环:交互程序的标准配件
while True:
    age_text = input("请输入年龄(0-120):").strip()

    if not age_text.isdigit():             # isdigit():字符串是否全是数字字符
        print("请输入数字!")               # (新方法,昨天四组方法的编外补充)
        continue

    age = int(age_text)                     # 走到这里,保证能安全转换,不会 ValueError
    if age < 0 or age > 120:
        print("年龄超出合理范围!")
        continue

    break                                   # 通过全部校验,带着合法的 age 离开循环

print(f"校验通过,年龄:{age}")
```

注意 `isdigit()` 的登场解决了 Day 01 的另一个痛:当时 `int("二十八")` 直接崩溃(ValueError),现在**先检查再转换**,程序稳如老狗。这个"校验循环"模式请收进工具箱,下午的猜数字和菜单系统都要用。(严谨说明:`isdigit()` 对 `"-5"` 返回 False——负号不是数字字符,所以负数会在第一关就被拦下,正好符合需求;但它也拦掉了合法的小数输入,完美的通用方案要等 Day 10 的 try/except。)

## 2.4 for 循环:对一批东西挨个处理

while 是"看条件重复",for 是"**看清单重复**":对一个序列里的每个元素,执行一遍循环体。昨天作业编程题 4 的欠账,当场结清:

```python
# 昨天:检查 3 个违禁词要写 3 行,500 个要写 500 行
# 今天:for 循环版,500 个词也是这三行
text = input("请输入内容:")

banned_words = ["赌博", "诈骗", "刷单"]        # 列表:装一批值的容器(明天的主角,今天先用)
for word in banned_words:                     # 读法:"对 banned_words 里的每一个 word"
    if word in text:                          # 注意:这两个 in 不是一个东西!见下方说明
        print(f"检测到违禁词:{word}")
```

读法示范:`for word in banned_words:` 读作"**对 banned_words 里的每一个元素(取名叫 word),执行下面的事**"。`word` 是你现起的名字,叫 `w`、叫 `item` 都行,但**见名知义**的老规矩不变。

有个必须澄清的撞名:第一行的 `in` 是 for 语法的固定组成部分("从…里遍历");第二行的 `in` 是昨天学的包含判断运算符("是否包含")。两个 in 拼写相同、含义不同,靠位置区分——for 后面的 in 属于 for,其他地方的 in 是运算符。

for 能遍历的不只列表,昨天的老朋友字符串也是序列:

```python
# 遍历字符串:一个字符一个字符地过
for ch in "RAG":
    print(f"字符:{ch}")
# 输出三行:R、A、G
```

## 2.5 range:数字序列生成器

"重复 N 次"、"从 1 数到 100"这类需求,不需要手写一个列表,`range()` 现场生成数字序列:

```python
# range(终点):从 0 开始,含头不含尾(切片的老规矩,通用!)
for i in range(5):
    print(i)               # 0 1 2 3 4  —— 5 个数,没有 5

# range(起点, 终点)
for i in range(1, 6):
    print(i)               # 1 2 3 4 5

# range(起点, 终点, 步长)
for i in range(0, 101, 10):
    print(i)               # 0 10 20 ... 100

# 倒数:步长为负
for i in range(5, 0, -1):
    print(i)               # 5 4 3 2 1
print("发射!")
```

`i` 是 index 的缩写,循环计数变量的行业惯用名(嵌套时依次用 j、k)。**"含头不含尾"再次出现**——切片、range,以后还有更多场合,Python 全家都遵守这个约定,一次记住处处适用。

for + range 的实用场景:**"重复 N 次"**,哪怕循环体里根本不用 i:

```python
# 场景:API 调用失败重试 3 次(Day 13 重试装饰器的雏形,先看形状)
for attempt in range(1, 4):
    print(f"第 {attempt} 次尝试调用 API……")
    # Day 12 之后,这里是真实的 requests 调用
```

## 2.6 for vs while:怎么选?

| | for | while |
|---|---|---|
| 适用 | **重复次数/对象确定**:遍历列表、重复 N 次 | **重复次数未知**:直到用户说退出、直到答对 |
| 心智模型 | "对这批东西,每个来一遍" | "只要还满足条件,就再来一遍" |
| 典型场景 | 违禁词逐个查、批量处理文档(Day 11) | 交互主循环(Day 14)、重试直到成功、Agent 循环(Day 39) |

经验法则:**能用 for 就用 for**(不会死循环,更安全);"待命等指令"类需求才用 `while True`。

## 2.7 循环与 else 的冷知识 + 累加器模式

两个收尾知识点。第一个是 Python 特有的小众语法,面试可能问到:**for/while 可以带 else,循环没被 break 打断、自然跑完时执行 else**:

```python
# 场景:检查违禁词,一个都没有时给出"通过"结论
banned_words = ["赌博", "诈骗", "刷单"]
text = "今天天气不错"

for word in banned_words:
    if word in text:
        print(f"驳回:含违禁词 {word}")
        break
else:                          # 注意缩进:else 对齐 for,不是对齐 if!
    print("审核通过")           # 只有循环从头到尾没 break 才执行
```

第二个是使用率 100% 的**累加器模式**:循环外初始化一个"篮子",循环里往里攒:

```python
# 数字累加:1 加到 100
total = 0                      # 篮子:累加器,初始为 0
for i in range(1, 101):
    total += i                 # 每轮往篮子里加
print(total)                   # 5050

# 字符串累加:昨天预告过的流式输出雏形
answer = ""                    # 篮子:空字符串
for chunk in ["大模型", "正在", "逐字", "返回"]:      # 模拟大模型分块吐字
    answer += chunk            # Day 24 的真实代码,今天用假数据跑通形状
    print(f"当前已收到:{answer}")
print(f"完整回答:{answer}")

# 计数器:统计一句话里的元音字母数
count = 0
for ch in "large language model":
    if ch in "aeiou":
        count += 1
print(f"元音数量:{count}")     # 7
```

累加器三件套——**数字累加(total)、字符串拼接(answer)、条件计数(count)**——是今后所有统计类代码的地基,Day 11 的词频统计、Day 34 的 RAG 评估指标计算,底下全是它。

### 代码实现

新知识点先行:**random 模块**。Python 自带一批"工具箱"(标准库),用 `import` 取用,Day 10 会系统讲,今天先用两行:

```python
# =============================================
# 猜数字游戏
# 需求编号:REQ-D03-001
# 知识点:while True 主循环、输入校验、if/elif/else、计数器
# =============================================
import random                          # 引入随机数工具箱(标准库,无需安装)

# randint(a, b):返回 a 到 b 之间的随机整数——注意这个是"含头又含尾"的少数派!
answer = random.randint(1, 100)
count = 0                              # 计数器:有效猜测次数

print("=" * 40)
print("猜数字:我已想好 1-100 之间的一个整数")
print("=" * 40)

while True:
    # ---- 输入校验(不合法不计次) ----
    guess_text = input("你猜:").strip()

    if not guess_text.isdigit():       # 非数字(含负号、小数点、空串)一律拦下
        print("请输入 1-100 的整数!")
        continue                       # 这把不算,重新输入

    guess = int(guess_text)            # 过了 isdigit,转换绝对安全
    if guess < 1 or guess > 100:
        print("超出范围,请输入 1-100!")
        continue

    # ---- 有效猜测:计数 + 判断 ----
    count += 1

    if guess > answer:
        print("大了 ↓")
    elif guess < answer:
        print("小了 ↑")
    else:
        # 猜中:根据次数给评价,然后退出
        print(f"猜中了!答案是 {answer},共用 {count} 次")
        if count <= 4:
            print("评价:运气爆棚!")
        elif count <= 7:
            print("评价:二分搜索高手!")
        else:
            print("评价:再接再厉~")
        break                          # 游戏结束,砸破 while True

print("感谢游玩!")
```

**玩后思考(课堂讨论)**:想最快猜中,策略是什么?答案:每次猜区间正中间——50、25、37……每猜一次排除一半,100 个数最多 7 次必中(2 的 7 次方 = 128 > 100)。这个策略叫**二分查找**,是计算机科学最经典的算法之一;Day 29 讲向量数据库的检索加速时,"每一步排除一半"的思想会以更高级的形态重现。你刚才玩游戏悟出来的,就是算法。

## 3.2 实操二:九九乘法表(15:10 - 15:50)

### 需求:打印标准的下三角九九乘法表

```
1×1=1
1×2=2  2×2=4
1×3=3  2×3=6  3×3=9
...
1×9=9  2×9=18 ... 9×9=81
```

### 先想清楚再写:嵌套循环的空间感

观察目标输出的结构:**9 行;第 n 行有 n 个算式;第 n 行的算式是 1×n 到 n×n**。"行"是一层循环,"行内的算式"是另一层循环——**循环套循环,外层走一步,内层跑全程**:

```python
# =============================================
# 九九乘法表:嵌套 for 循环的经典训练
# 外层 i = 行号(1~9),内层 j = 列号(1~i)
# =============================================
for i in range(1, 10):             # 外层:第 1 行到第 9 行
    for j in range(1, i + 1):      # 内层:第 i 行有 i 个算式(range 含头不含尾,所以 i+1)
        # end="\t" 不换行,用制表符分隔,保证列对齐(Day 01 的 end 参数上岗)
        print(f"{j}×{i}={j * i}", end="\t")
    print()                        # 内层跑完一行,补一个换行(空 print = 只换行)
```

三个咀嚼点:

1. **内层的终点是 `i + 1`**:第 3 行要 3 个算式(j = 1,2,3),range 含头不含尾,所以写 range(1, 4) 即 range(1, i+1)。外层变量出现在内层的范围里——这是嵌套循环的精髓:**内层的行为随外层变化**;
2. **`end="\t"`**:Day 01 学的 end 参数第一次干正事。`\t` 是制表符(昨天转义字符的成员),自动对齐到下一个制表位,表格因此整齐;
3. **`print()` 的位置**:它缩进在外层、内层之外——每完成一行才换行。把它错误缩进到内层里试试(每个算式后都换行,表就竖过来了),**缩进层级决定归属,这个实验值得做一次**。

**嵌套循环的运行量感觉**:外层 9 次 × 内层平均 5 次 = 45 个算式。如果两层都是 1 万次,就是 1 亿次运算——嵌套循环的成本是相乘的。Day 20 计算"每个问题和知识库里每条文档的相似度"就是这样的双层循环,到时你就明白为什么需要向量数据库来加速(Day 29)。

### 代码实现

```python
# =============================================
# 简易菜单系统:三日小工具合集
# 需求编号:REQ-D03-002
# 架构:主循环(while True) + 分发器(if/elif)
# 这是 Day 14《命令行 AI 助手》的骨架直系祖先
# =============================================
import random

usage_count = 0                                # 会话计数器:累加器模式

while True:
    # ---- 显示菜单 ----
    # 每轮循环都重新打印,保证功能用完回来还能看到选项
    print()
    print("=" * 36)
    print("      三日小工具合集 v1.0")
    print("=" * 36)
    print("  1. 文本清洗(Day02 成果)")
    print("  2. 手机号脱敏(Day02 成果)")
    print("  3. 猜数字游戏(Day03 成果)")
    print("  0. 退出")
    print("-" * 36)

    choice = input("请选择功能:").strip()      # 清洗输入,老习惯

    # ---- 分发器:根据选择走不同分支 ----
    if choice == "1":
        # 功能 1:文本清洗(昨天流水线的浓缩版)
        raw = input("请输入待清洗文本:")
        clean = " ".join(raw.strip().lower().split())     # F1+F2+F4 一行流
        clean = clean.replace("垃圾", "**").replace("傻子", "**")   # F3
        print(f"清洗结果:{clean}")
        usage_count += 1

    elif choice == "2":
        # 功能 2:手机号脱敏(带校验循环,今天上午的成果)
        while True:
            phone = input("请输入 11 位手机号:").strip()
            if phone.isdigit() and len(phone) == 11:      # 全数字 且 长度 11
                break
            print("格式不对,请输入 11 位数字!")
        print(f"脱敏结果:{phone[:3]}****{phone[-4:]}")
        usage_count += 1

    elif choice == "3":
        # 功能 3:猜数字(简化版:不限范围校验,聚焦主流程)
        answer = random.randint(1, 100)
        count = 0
        print("我想好了一个 1-100 的数")
        while True:
            guess_text = input("你猜:").strip()
            if not guess_text.isdigit():
                print("请输入数字!")
                continue
            guess = int(guess_text)
            count += 1
            if guess > answer:
                print("大了 ↓")
            elif guess < answer:
                print("小了 ↑")
            else:
                print(f"猜中!共 {count} 次")
                break
        usage_count += 1

    elif choice == "0":
        # 退出:先统计,再砸破主循环
        print(f"本次会话共使用功能 {usage_count} 次,再见!")
        break

    else:
        # 兜底分支:一切非法输入到这里,程序永不裸奔
        print(f"没有选项 [{choice}],请输入 0-3")
```

# 【常见错误与排错手册】Day 03 专属篇

**错误 1:if 行尾忘冒号。** `SyntaxError: expected ':'`。凡是"下面挂着代码块"的行(if/elif/else/while/for),行尾必须冒号。

**错误 2:缩进错乱。** 三种报错都见过一遍就不慌了:
- `IndentationError: expected an indented block` → if/for 下面该缩进的行没缩进;
- `IndentationError: unexpected indent` → 不该缩进的行缩进了;
- `IndentationError: unindent does not match any outer indentation level` → 缩进深浅不一(通常是 Tab 和空格混用,VS Code 右下角可查看/统一)。

**错误 3:`if age = 18` 用了赋值号。** `SyntaxError: invalid syntax. Maybe you meant '==' ...?`——新版 Python 的报错甚至会直接提醒你。赋值一个等,比较两个等,Day 02 的预言今天应验。

**错误 4:死循环忘了出口。** 症状:程序不停刷屏或卡住不动。急刹车:`Ctrl + C`。排查:while 的条件变量在循环体里有没有被更新?`while True` 里有没有可达的 break?

**错误 5:break 想砸两层循环,只砸了一层。** break 只能砸破**当前这一层**循环。嵌套循环想全退,今天的临时方案是加标志变量(`found = True` 然后外层判断),优雅方案等 Day 06 的函数 return。

**错误 6:`range(1, 9)` 想要 1 到 9,少了最后一个。** 含头不含尾,想到 9 就写 `range(1, 10)`。和切片同一个约定,错第二次就该罚抄了。

**错误 7:循环里改比较的对象,结果诡异。** 比如边遍历列表边删元素(明天学列表后高发,先打预防针):遍历时不要修改正在被遍历的容器,这是铁律,Day 04 详解。

**错误 8:else 缩进对错了对象。** for-else 结构里,else 必须与 for 对齐;往里多缩 4 格就变成了 if 的 else,含义天差地别。缩进不只是"多少格",还有"对齐谁"。

# 【附录】课堂答疑实录(晚自习整理)

**问 1:为什么 Python 要用缩进当语法?大括号不是更明确吗?**

答:这是 Python 最有争议也最有远见的设计。理由:用大括号的语言里,程序员**依然**会缩进代码(为了给人看),于是同一份结构信息存在两份——大括号给机器看,缩进给人看,两者不一致时(缩进骗人、大括号说真话)就是 bug 温床。Python 干脆合二为一:给人看的缩进就是给机器看的语法,所见即所得。代价是你必须严格对待空格,收益是全世界的 Python 代码长得都一样整齐。习惯之后(大约还需三天),你会觉得大括号才别扭。

**问 2:`while True` 看起来很危险,公司代码里真的允许写吗?**

答:允许,而且大量存在——Web 服务器的主体就是"永远循环:等请求 → 处理 → 回应答",Day 23 你会亲眼看到 FastAPI 底层就是这么活着的。危险的不是 while True 本身,而是**没有可达的出口**。工程上的安全清单:① 循环体里必须有可达的 break(或 return);② 交互程序要处理 Ctrl+C(Day 10 的异常处理会讲优雅退出);③ 循环体里如果有等待外部资源的操作(如调 API),要设超时(Day 13)。带出口的 while True 是骨架,没出口的是事故。

**问 3:elif 和连续写多个 if 有什么区别?我试了输出好像一样。**

答:输出可能碰巧一样,机制完全不同。elif 链是**互斥**的:命中一个,其余全跳过;连续 if 是**独立**的:每个都要检查、都可能执行。分数 95 的例子——elif 版只打印"优秀";如果全改成 if,"优秀""良好""及格"会**全部打印**(95 同时满足三个条件)。判断标准:各分支互斥(一个人只有一个等级)用 elif;各条件可以同时成立(密码检查器里"有大写"和"有数字"可以都满足)用独立 if。今天作业的密码强度题就是"独立 if"的典型,做的时候体会一下。

**问 4:for 循环的变量 i,循环结束后还在吗?**

答:在,而且保留最后一次的值。`for i in range(5)` 跑完后,i 是 4(不是 5!最后一次成功赋的值)。这是 Python 与许多语言不同的地方(循环变量不是循环的"私有财产")。实用后果:循环后可以直接用 i 做判断,比如 for-else 之外的另一种"记录在哪停下"的手法。但也有坑:两个连续循环都用 i,第二个忘了初始化时不报 NameError,悄悄用了上一个循环的残值。命名认真点(word、email、attempt)能天然避开。

**问 5:isdigit、isnumeric、isdecimal 有三个,用哪个?**

答:日常用 isdigit 就够。三者对普通 0-9 数字行为一致,差异在罕见字符(罗马数字、汉字数字、上标数字)的判定上,应用开发几乎碰不到。真正要记住的是三者共同的局限:**都不认小数点和负号**,所以它们只适合校验"非负整数输入"。要校验小数,用今天作业里 `replace(".", "", 1).isdigit()` 的技巧;要一劳永逸,等 Day 10 的 try/except——直接尝试转换、失败就捕获,是 Python 社区更推崇的风格("请求原谅比请求许可容易",EAFP 原则,Day 10 详讲)。

**问 6:嵌套循环最多能嵌几层?我看乘法表两层就有点晕。**

答:语法上没有上限,工程上两层是日常、三层是警戒线、四层基本可以断定设计有问题(要么该拆函数,要么该换数据结构或算法)。晕是正常的——嵌套循环的"心智负担"是乘法级的。给你一个止晕技巧:**在纸上画表格人肉执行**,外层一行、内层一列,把每轮的 i、j、输出写下来,跑两三轮感觉就出来了。这个"人肉执行"(行话叫 trace/走查)是调试的原始但极有效的手段,读程序题做错的同学尤其要练。

**问 7:LeetCode 题目里的 `class Solution:` 和 `def` 是什么?现在需要懂吗?**

答:不需要,照抄模板往里填就行。def 是定义函数(Day 06)、class 是定义类(Day 08),平台用这个格式是为了自动测试你的代码。你现在只负责中间的逻辑行。有个学习技巧:把"提前遇到、暂时不懂"的语法记到一个 `questions.md` 里,等学到那天回来划掉——划掉的那一刻很有成就感,而且你会发现提前眼熟过的语法学得特别快。

**问 8:菜单系统里,为什么判断 `choice == "1"` 是字符串比较,不转成 int?**

答:好眼力,这是刻意的。两个原因:① 菜单选项本质是"指令代号"不是"数量",不参与算术,没必要转;② 更重要的是健壮性——用户输入 "abc" 时,`int(choice)` 直接 ValueError 崩溃,而字符串比较 `"abc" == "1"` 安静地得 False,走进 else 兜底分支给出友好提示。**"能不转换就不转换,在边界上保持数据原样"**是防御式编程的一个小原则。同理,Day 14 的 /exit 指令判断也是纯字符串比较。

**问 9:今天信息量好大,感觉 if 懂了,循环还是虚,怎么办?**

答:正常,而且在预期内——课程把流程控制放在一天,就是知道它需要"当天懂 + 一周熟"。接下来的安排已经替你设计好了循环的复利:明天遍历列表(for 天天见)、Day 05 遍历字典、Day 07 周测综合项目(通讯录,主循环 + 分发器再写一遍)、Day 11 批量处理文件(for 的大场面)。你不需要今天就"熟",只需要今天的三个实操都亲手跑通。七天后回看今天的代码,你会奇怪自己当时为什么觉得难。

# 【课堂笔记】Day 03 知识点速查表

**if / elif / else**
- 结构:`if 条件:` + 冒号 + 缩进 4 格;elif 可多个;else 兜底不带条件
- elif 从上到下,**命中即退出**;条件顺序按从严到宽单调排列
- 嵌套超 3 层要重构:优先"合并条件平铺分支"
- 真值上岗:`if user_input.strip():` 非空才处理

**while**
- 三要素:初始化、条件、更新;忘更新 = 死循环;急刹车 `Ctrl + C`
- `while True` + `break`:交互程序标准骨架(→ Day 14 AI 助手)
- 输入校验循环:`isdigit()` 先检查再 `int()`,continue 重来,break 通过

**for + range**
- `for x in 序列:`——列表、字符串都能遍历

- `range(n)` 从 0 起 n 个数;`range(a, b)` 含 a 不含 b;`range(a, b, -1)` 倒数
- for vs while:次数确定用 for,"待命等指令"用 while True

**break / continue**:不玩了 / 这把不算再来
**for-else**:循环没被 break 才执行 else(找东西没找到的兜底)

**累加器三件套**:`total += i`(求和)、`answer += chunk`(拼接,流式输出雏形)、`count += 1`(计数)

**架构:主循环 + 分发器**(今天最重要的资产)
