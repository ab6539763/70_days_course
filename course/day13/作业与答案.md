### 选择题答案与解析

**1. B。** @ 只是"用加强版顶替原函数"的缩写,没有魔法。
**2. C。** 装饰器头号事故:wrapper 里必须 `return func(...)`。

**5. B。** 交货暂停 vs 交卷走人。
**6. B。** 生成器惰性:next/for 才驱动。协程函数同理(调用不执行,await 才跑)。
**7. C。** delay = base × 2^(n-1):1、2、4。
**8. C。** example 是说明书(进库),真身含密钥(不进)。
**9. B。** 异步的本质是"等待重叠",只对"等得多"的任务有效。
**10. C。** 同步阻塞卡住调度器。异步世界用 asyncio.sleep / httpx。

```python
def d(func):
```

```python
def countdown(n):

g = countdown(3)

```

**3.**

```python
import functools

def tag(label):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            return f"[{label}] {func(*args, **kwargs)}"
        return wrapper
    return decorator

@tag("重要")
@tag("紧急")
def notice(text):
    return text

print(notice("服务器维护"))
```

**4.**

```python
import asyncio, time

async def task(name, seconds):
    await asyncio.sleep(seconds)
    return name

async def main():
    start = time.time()
    r = await asyncio.gather(task("A", 2), task("B", 1), task("C", 2))
    print(r, round(time.time() - start))

asyncio.run(main())
```

### 读程序题答案与解析

**1.** `14`。wrapper 把原函数结果乘 2:(3+4)×2。装饰器改变行为的最小示例。

**2.**
```
3 2
[1, '发射!']
```
两次 next 取走 3、2;list(g) 收走剩余的 1 和最后的 "发射!"。生成器的状态在多次索取之间持续保留。

**3.** `[重要] [紧急] 服务器维护`。叠放装饰器自下而上装、自上而下生效:先 @tag("紧急") 贴身包住(内层),再 @tag("重要") 包外层——调用时外层先执行,把内层结果套上 [重要]。

**4.** `['A', 'B', 'C'] 2`。gather 并发:总耗时 = 最慢的那个(2 秒),不是 2+1+2=5;结果顺序与传入顺序一致(不是完成顺序)——gather 替你按序收集,这是它比手动管理任务省心的地方。

### 编程题 1:@timer 计时装饰器

写 `@timer`:打印被装饰函数的执行耗时(datetime 或 time.time 计时),规范齐全(wraps、转发、return)。用它装饰一个 sleep 0.5 秒的函数验证。**加分项**:让它可以和 @retry 叠放,并思考谁在外层更合理(答案写注释里)。

**参考答案(homework/timer_decorator.py):**

```python
# =============================================
# Day 13 作业 · 编程题 1:@timer 计时装饰器
# =============================================
import functools
import time


def timer(func):
    """计时装饰器:打印函数执行耗时。"""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)           # 干正事
        elapsed = time.time() - start
        print(f"[timer] {func.__name__} 耗时 {elapsed:.3f}s")
        return result                            # 递出去!
    return wrapper


@timer
def slow_task():
    """模拟耗时任务。"""
    time.sleep(0.5)
    return "完成"


print(slow_task())

# 叠放思考:@timer 应该在 @retry 外层——
#   @timer
#   @retry()
#   def chat(...): ...
# 这样计的是"含全部重试的总耗时"(用户真实等待时间);
# 反过来则每次重试各计一次,得到的是单次尝试耗时。
# 两种都有用途,但监控用户体验时要总耗时,所以默认 timer 在外
```

### 编程题 2:批量问答生成器 ★(生成器 + 模型的合体)

写生成器函数 `qa_stream(model, questions: list)`:对每个问题调用模型,**逐个 yield** `(问题, 回答)` 元组(而不是攒成列表一次性返回)。消费端 for 循环边收边打印。用 FakeModel 验证。思考并在注释里回答:生成器版比"返回完整列表"版好在哪?(提示:第 3 个问题还没答完时,用户已经能看到第 1 题的答案)

**参考答案(homework/qa_stream.py):**

```python
# =============================================
# Day 13 作业 · 编程题 2:批量问答生成器
# 生成器版的价值:边生产边交付——
#   列表版:10 个问题全部答完(30秒)才能看到第一个答案;
#   生成器版:第一个答案 3 秒就交付,用户体验质变。
# 这就是"流式思想"在批处理场景的应用,Day 24 的 SSE 是它的网络版
# =============================================
import sys, os
sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", "code"))

from chatlib_v3 import FakeModel, ChatLibError


def qa_stream(model, questions: list):
    """逐个提问,逐个 yield (问题, 回答);单题失败 yield 错误标记,不中断。"""
    for q in questions:
        messages = [
            {"role": "system", "content": "简洁回答,50字以内"},
            {"role": "user", "content": q},
        ]
        try:
            yield (q, model.chat(messages))      # 答完一个交付一个
        except ChatLibError as e:
            yield (q, f"[失败:{e}]")             # 军规:单题失败不中断整批


if __name__ == "__main__":
    model = FakeModel()
    questions = ["什么是装饰器?", "什么是生成器?", "什么是异步?"]

    for q, a in qa_stream(model, questions):     # 边收边打印
        print(f"问:{q}\n答:{a}\n")
```

```python
# =============================================
# Day 13 作业 · 编程题 3⑤:环境自检脚本
# 以后每个项目的标准启动自检:缺谁报谁,全齐放行
# =============================================
import os
import sys

from dotenv import load_dotenv

load_dotenv()

REQUIRED_VARS = ["DEEPSEEK_API_KEY"]             # 列表驱动:项目变了只改这里
OPTIONAL_VARS = ["APP_ENV"]


def check_env() -> bool:
    """检查必需环境变量;缺失则逐个报告,返回是否通过。"""
    missing = [v for v in REQUIRED_VARS if not os.environ.get(v)]
    if missing:
        print("环境自检失败,缺少以下变量:")
        for v in missing:
            print(f"  - {v}(请在 .env 中配置,参考 .env.example)")
        return False

    for v in REQUIRED_VARS:
        value = os.environ[v]
        print(f"  ✓ {v} = {value[:6]}...(已脱敏)")     # Day 02 脱敏手艺:绝不打印全值
    for v in OPTIONAL_VARS:
        print(f"  · {v} = {os.environ.get(v, '(未设置,使用默认)')}")
    return True


if __name__ == "__main__":
    if not check_env():
        sys.exit(1)                              # 非零退出码:告诉调用方"自检失败"
    print("环境自检通过,可以启动")
```

**思考题 1:** @retry 里的 time.sleep 在异步世界会堵死调度器(今天的纪律)。如果未来要给 FastAPI 里的异步函数加重试,这个装饰器要怎么改?列出至少两处必须的改动。

**参考答案要点:** ①wrapper 要变成 `async def wrapper`,内部 `return await func(...)`(被装饰的是协程函数);②`time.sleep(delay)` 换成 `await asyncio.sleep(delay)`(不堵调度器);③装饰器需要判断被装饰函数是否协程(`asyncio.iscoroutinefunction`),或干脆写两个版本(retry / async_retry)。这道题的意义:**同步世界的工具搬进异步世界,所有"会等"的操作都要换成异步版**——这是 Day 23 之后读 FastAPI 生态代码时反复出现的模式。业界的 tenacity 库同时支持两种,原理正是如此。
