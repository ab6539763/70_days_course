# 【旁白解读】今天这一课,在整个 70 天里处于什么位置?

在正式开始之前,请允许我先用五分钟,把今天放进整个课程的地图里。这个"旁白解读"环节,以后每天的课件开头都会有——它的作用是让你永远知道自己在哪里、从哪里来、要到哪里去。学习最怕的不是难,而是迷路。

你报名的是一门"大模型应用开发"课程。你可能昨天晚上还在想:我是来学 ChatGPT 的,为什么第一天要学 Python?为什么要装一堆软件?我想先回答这个问题,因为它决定了你今天听课的心态。

**大模型应用开发,本质上是一个"翻译"工作:把业务需求,翻译成一段能和大模型对话的程序。** 大模型(比如 GPT、DeepSeek、通义千问)本身是别人训练好的,放在云端,你不需要造它;你要做的,是写一段程序,把用户的问题发给它、把它的回答接回来、在中间加上你的业务逻辑(比如查知识库、调工具、存历史记录)。而这段"程序",全世界 90% 以上的大模型应用,都是用 Python 写的。

所以我们 70 天的路线是这样铺的:

```
Day 01 - 14   Python 编程基础        →  你能写程序了
Day 15 - 24   大模型理论与 Prompt     →  你能指挥大模型了
Day 25 - 38   LangChain 与 RAG      →  你能给大模型外挂知识库了(项目二)
Day 39 - 50   Agent 智能体           →  你能让大模型自己干活了(项目三)
Day 51 - 57   微调与部署             →  你能训练并上线自己的模型了
Day 58 - 70   毕业设计与就业冲刺      →  你能拿着作品去面试了
```

今天是 Day 01,处在整条路线的最起点。今天结束时,你会拥有四样东西:

1. 一个完整可用的 Python 开发环境(Python 3.10+、VS Code、国内镜像源);
2. 你人生的第一个 Python 程序;
3. 一个能收集用户输入、做简单处理、格式化输出的"个人信息卡片"程序——别小看它,它的结构和 Day 14 的"AI 对话助手"、Day 30 的"知识库问答系统"是同构的:**输入 → 处理 → 输出**;
4. 一个配置好的 Git + GitHub 账号,从今天起,你写的每一行代码都会被记录下来,70 天后,这份提交记录就是你简历上最有说服力的一行。

**今天的内容会被明天怎么用?** 明天(Day 02)我们学字符串处理,你今天写的"个人信息卡片"会被升级:加上文本清洗功能(去空格、统一格式)。后天(Day 03)加上条件判断(年龄合法性校验)。Day 05 它会学会把信息存成 JSON。Day 12 它会第一次连上大模型 API。这个小程序会像滚雪球一样,一路滚到 Day 14 变成完整的 AI 助手。所以,今天请务必把它亲手敲出来。

# 上午 · 第一节(9:00 - 10:00):大模型行业全景与职业路径分析

## 1.1 我们先从三个真实的招聘需求说起

学任何东西之前,先看市场要什么。下面是 2025 - 2026 年招聘网站上三个真实存在的岗位画像(公司名隐去,内容为典型 JD 的归纳):

**岗位一:大模型应用开发工程师(某电商公司,月薪 20K - 35K)**

> 岗位职责:
> 1. 负责智能客服系统的开发与迭代,基于大模型 API 构建多轮对话能力;
> 2. 搭建商品知识库问答系统(RAG),优化检索与回答质量;
> 3. 开发内部效率工具(如自动生成商品文案的 Agent)。
>
> 任职要求:
> 1. 熟练使用 Python,熟悉 FastAPI 等 Web 框架;
> 2. 熟悉 LangChain / LlamaIndex 等大模型开发框架;
> 3. 熟悉向量数据库(Milvus / Chroma),理解 Embedding 与语义检索;
> 4. 有 Prompt 工程实践经验,了解 Function Calling。

**岗位二:AI 产品工程师(某 SaaS 创业公司,月薪 18K - 30K)**

> 1. 快速验证 AI 功能原型,将大模型能力集成进现有产品;
> 2. 会用 Dify / Coze 等平台快速搭建工作流,也能用代码实现复杂逻辑;
> 3. 懂 Prompt 调优,能设计评估方案衡量 AI 功能效果。

**岗位三:大模型算法工程师(初级)(某金融科技公司,月薪 25K - 40K)**

> 1. 负责垂直领域模型微调(LoRA / QLoRA),构建训练数据集;
> 2. 负责模型量化与推理服务部署(vLLM / Ollama);
> 3. 熟悉 Docker,有模型上线经验优先。

现在请你做一件事:把这三个 JD 里你看不懂的词圈出来。我猜你圈出来的大概是:RAG、LangChain、向量数据库、Embedding、Prompt 工程、Function Calling、Agent、Dify、LoRA、量化、vLLM、Docker、FastAPI……

**好消息是:这些词,恰好就是我们 70 天课表的目录。** 你现在看不懂的每一个词,课表里都有一个对应的"Day"。70 天后你再回来看这三个 JD,每一条你都能说出"这个我做过,项目在我 GitHub 上"。这就是这门课的设计逻辑——**我们不是从知识出发,而是从岗位要求倒推出来的课程**。

## 1.2 大模型行业的分层地图:你要进入的是哪一层?

很多零基础同学对"AI 行业"的想象是模糊一团的。我们把它切成清晰的四层,你就知道自己的位置了。

```
┌─────────────────────────────────────────────────────────┐
│  第 4 层:应用层(我们的主战场)                              │
│  做什么:智能客服、知识库问答、办公助手、行业 Agent           │
│  用什么:Python + API + LangChain + 向量库 + FastAPI       │
│  门槛:中(本课程 70 天可达)   岗位数量:★★★★★            │
├─────────────────────────────────────────────────────────┤
│  第 3 层:平台/工具层                                       │
│  做什么:开发框架(LangChain)、推理引擎(vLLM)、             │
│          低代码平台(Dify/Coze)                            │
│  门槛:较高(需要扎实工程功底)   岗位数量:★★★              │
├─────────────────────────────────────────────────────────┤
│  第 2 层:模型层                                            │
│  做什么:预训练、对齐(SFT/RLHF)、微调、评测                 │
│  用什么:PyTorch、大规模 GPU 集群                           │
│  门槛:高(通常要求硕博+论文)   岗位数量:★★                │
├─────────────────────────────────────────────────────────┤
│  第 1 层:算力/基础设施层                                    │
│  做什么:GPU 芯片、云计算、机房、网络                        │
│  门槛:极高(资本+硬件密集)   岗位数量:★                   │
└─────────────────────────────────────────────────────────┘
```

请注意几个关键判断:

- **越往下,玩家越少、门槛越高**。第 1、2 层是英伟达、OpenAI、阿里、字节这类巨头的游戏,零基础转行者短期内进不去,也不必进去。
- **越往上,岗位越多、越贴近业务**。每一家想用 AI 的公司——银行、医院、学校、律所、工厂、电商——都需要应用层开发者,但它们绝大多数不需要自己训练模型。这就像每家公司都需要会用 Excel 的人,但极少有公司需要开发 Excel 的人。
- **应用层的核心竞争力不是数学,而是工程能力 + 业务理解**。这正是转行者、产品经理的机会所在:你过去的行业经验(懂电商、懂金融、懂教育)在应用层是加分项,而不是无关项。

本课程的定位非常明确:**把你送进第 4 层(应用层),并让你摸到第 2 层的边(微调,Day 51 - 55),让你在面试里既有广度又有亮点。**

## 1.3 应用层工程师的一天:你未来的工作长什么样?

为了让"大模型应用开发工程师"这个头衔具体化,我们看一个虚构但高度真实的场景。

> 小林,26 岁,原来做电商运营,经过培训转行,现在在一家做企业服务的公司当大模型应用开发工程师,入职 8 个月。
>
> **上午 10:00**,产品经理提需求:"客户反馈知识库问答有时候答非所问,能不能优化一下?" 小林打开日志系统,发现是检索环节召回的文档不相关。他调整了文本分块大小(chunk_size 从 1000 调到 500),又加了一层重排序模型(rerank),用测试集跑了一遍评估,答案相关性从 72% 提升到 89%。——这套操作,是我们 Day 28 - 34 的内容。
>
> **下午 14:00**,他继续开发新功能:让 AI 客服能直接查订单状态。他写了一个"查订单"的工具函数,注册给大模型,模型判断用户想查订单时就自动调用这个函数。——这是 Day 19 的 Function Calling 和 Day 40 的 Agent 工具开发。
>
> **下午 17:00**,新功能开发完,他把代码提交到 Git,打包成 Docker 镜像,部署到测试环境,通知测试同事验收。——Git 是今天晚自习的内容,Docker 是 Day 56。
>
> 他的日常里,**没有一行数学公式,没有训练过任何模型**,但他解决的是公司真金白银的业务问题,这就是应用层工程师的价值。

## 1.4 转行者最关心的五个问题(FAQ)

**Q1:我完全没写过代码,真的能学会吗?**
能,但有条件。条件不是智商,而是**每天 6 - 8 小时投入 × 70 天不断线**。编程是肌肉记忆型技能,和学车一样:没人靠看驾驶教学视频学会开车,你必须手放在方向盘上。本课程每天下午都是实操,晚上有作业,就是逼你把手放在键盘上。

**Q2:数学不好怎么办?**
应用层开发对数学的要求,大概相当于"会算折扣价"。课程里唯一接近数学的地方是 Day 20 的"余弦相似度"(判断两句话像不像),我们会用类比讲清楚,不推导公式。

**Q3:35 岁 / 30 岁转行晚不晚?**
大模型应用开发是 2023 年才爆发的方向,全行业最资深的从业者也就干了三年。在一个所有人都是新人的领域,年龄劣势被大幅稀释,你过去的行业经验反而是差异化优势。

**Q4:学完真的能找到工作吗?**
课程给你的是:4 个可写进简历的完整项目 + 一个有 70 天连续提交记录的 GitHub + 200 题面试题库 + 3 天面试特训(Day 67 - 69)。这些是"最大化你概率"的东西,剩下的取决于你投入的质量和求职期的执行力。我们不承诺结果,但我们保证你交付出去的每一个作品都经得起面试官深挖。

**Q5:AI 发展这么快,现在学的会不会很快过时?**
框架会过时,能力不会。本课程刻意分成两层:**底层能力**(Python、HTTP、JSON、Prompt 思维、检索思维、工程化习惯)十年内不会变;**上层工具**(LangChain 的某个版本、某个模型)会变,但你有了底层能力,换工具是一周的事。这也是为什么 Day 39 我们会先"不用框架手写一个 Agent"——理解了原理,任何框架都只是语法糖。

## 1.5 本课程的游戏规则

最后花三分钟讲清楚课程纪律,这些规则每一条都有明确目的:

1. **每日代码必须提交到 GitHub**(今晚学会怎么提交)。目的:积累你的公开作品记录,面试官真的会看。
2. **作业不允许跳过**。每天作业里都埋着第二天课程的"钩子",跳过作业,第二天上课会有明显的断层感。
3. **每周日周测**(Day 07、14、21……)。周测不是为了排名,是为了让你自己知道哪块没掌握,趁热补。
4. **三次阶段项目 + 一次毕业设计,全部要答辩**。答辩练的是"把技术讲给人听"的能力,这个能力在面试里和写代码同样重要。

# 上午 · 第二节(10:10 - 12:00):搭建你的开发环境

## 2.1 开始之前:理解你要装的三样东西分别是什么

零基础同学装环境最大的痛苦,是"不知道自己在装什么,只是机械地跟着点下一步",一旦出错就束手无策。所以动手之前,先建立认知。今天要装三样东西:

| 要装的东西 | 它是什么 | 类比 |
|-----------|---------|------|
| Python 3.10+ | Python 语言的**解释器**:一个能读懂 Python 代码并执行它的程序 | 一位懂中文的翻译官,你写中文(Python 代码),他翻译给计算机听 |
| VS Code | **代码编辑器**:写代码的地方,带高亮、提示、补全 | 一个专业厨房。你也可以在记事本里写代码(在家煮泡面),但专业厨房让你效率高十倍 |
| pip 国内镜像源 | Python 的**包管理器下载加速配置** | 淘宝的"本地仓库":官方仓库在国外,下载慢;配置国内镜像后,从阿里/清华的服务器下载,秒级完成 |

这里要着重讲清楚一个初学者最容易混淆的概念:

> **Python 语言 ≠ Python 解释器 ≠ VS Code。**
> Python 语言是一套语法规则(像"中文语法");Python 解释器是执行这套语法的软件(像"懂中文的人");VS Code 只是个编辑器(像"一张书桌")。书桌上没有懂中文的人,你写的中文没人执行——所以**只装 VS Code 不装 Python,代码是跑不起来的**。这是第一天最高频的报错来源,先打好预防针。

## 2.2 安装 Python 3.10+(Windows 篇)

> 班里 Windows 用户占多数,以 Windows 11 为例逐步演示。macOS 同学看 2.3 节。

**第 1 步:下载安装包。**
打开浏览器,访问 Python 官网下载页 `https://www.python.org/downloads/`。如果官网访问缓慢,可以使用华为云镜像 `https://mirrors.huaweicloud.com/python/` 或淘宝镜像 `https://registry.npmmirror.com/binary.html?path=python/`,选择 **3.12.x** 版本(课程要求 3.10 以上,推荐 3.12,它对我们后面要用的所有库兼容性最好;暂时不要用最新的 3.13+,部分 AI 库适配需要时间——这是工程师的一个重要习惯:**生产环境永远用"最新减一"的稳定版**)。下载 `Windows installer (64-bit)`,文件名形如 `python-3.12.7-amd64.exe`。

**第 2 步:运行安装包——这一步有一个全班必错的坑。**
双击安装包,出现安装界面。**在点击"Install Now"之前,务必勾选界面最下方的 `Add python.exe to PATH` 复选框!**

这个勾选框是什么意思?PATH 是操作系统的"程序通讯录"。当你在命令行输入 `python` 时,系统会翻这本通讯录找"python 住在哪个文件夹"。不勾选,系统通讯录里没有它,你输入 `python` 就会得到经典报错:

```
'python' 不是内部或外部命令,也不是可运行的程序或批处理文件。
```

根据历届开班经验,**全班约三分之一的同学会漏掉这个勾选**。如果你已经装完才看到这句话,不用卸载重装:重新运行安装包 → 选 `Modify` → 下一步勾选 `Add Python to environment variables` 即可修复。

**第 3 步:验证安装。**
按 `Win + R`,输入 `cmd` 回车,打开命令提示符(黑窗口)。这个黑窗口的正式名字叫**终端(Terminal)**,它是你未来 70 天最亲密的伙伴之一——程序员用文字命令指挥计算机的地方。输入:

```bash
python --version
```

如果屏幕显示 `Python 3.12.7`(或你安装的版本号),恭喜,安装成功。再验证包管理器:

```bash
pip --version
```

显示类似 `pip 24.2 from C:\...` 即正常。pip 是随 Python 一起安装的"应用商店客户端",以后我们装任何第三方库(比如 Day 12 的 requests、Day 25 的 langchain)都靠它。

**第 4 步:体验交互模式(30 秒的仪式感)。**
在终端输入 `python` 回车,你会看到提示符变成 `>>>`——这是 Python 的交互模式,你说一句,它执行一句。输入:

```python
>>> 1 + 1
2
>>> print("你好,大模型")
你好,大模型
```

看到了吗?计算机听懂你的话了。输入 `exit()` 回车退出交互模式。交互模式适合做快速小实验,但正式代码要写在文件里——这就是待会儿 VS Code 的用武之地。

## 2.3 安装 Python 3.10+(macOS 篇)

macOS 自带一个古老的 Python(部分系统是 2.x 或旧 3.x),**不要用系统自带的**,我们装自己的:

方式一(推荐,简单):同 Windows,去官网下载 `macOS 64-bit universal2 installer`,双击 `.pkg` 一路下一步。macOS 安装包不需要勾选 PATH,安装器会自动配置。

方式二(进阶,可选):如果你已安装 Homebrew,终端执行 `brew install python@3.12`。

验证:打开"终端"(启动台搜索 Terminal),输入 `python3 --version`。注意 macOS 上命令是 **`python3`** 和 **`pip3`**(带个 3),课件后文写 `python` 的地方,macOS 同学自行替换,后面不再重复提醒。

## 2.4 配置 pip 国内镜像源

pip 默认从官方仓库 `pypi.org`(服务器在国外)下载库,国内网络环境下经常龟速甚至超时。我们把下载源换成清华大学的镜像——内容和官方完全同步,速度快几十倍。终端执行:

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

这条命令做了什么?它在你的用户目录下写了一个配置文件(Windows 在 `%APPDATA%\pip\pip.ini`,macOS 在 `~/.config/pip/pip.conf`),内容就是"以后下载都去清华服务器"。验证配置生效:

```bash
pip config list
```

输出 `global.index-url='https://pypi.tuna.tsinghua.edu.cn/simple'` 即成功。如果清华源偶尔维护,备选源(语法相同,换 URL 即可):

- 阿里云:`https://mirrors.aliyun.com/pypi/simple/`
- 中科大:`https://pypi.mirrors.ustc.edu.cn/simple/`
- 腾讯云:`https://mirrors.cloud.tencent.com/pypi/simple`

## 2.5 安装与配置 VS Code

**第 1 步:下载安装。** 访问 `https://code.visualstudio.com/`,下载对应系统的安装包。Windows 安装时建议把"通过 Code 打开"相关的勾选项全部勾上(方便以后右键文件夹直接用 VS Code 打开)。

## 2.7 初学者环境排错手册(上午部分)

环境问题不解决,后面全堵住,所以我们把第一天最高频的五个环境报错和解法直接列出来。**读懂报错信息本身就是今天的教学内容**:报错不是"电脑坏了",而是计算机在用它的方式告诉你哪里不对。

**报错 1:`'python' 不是内部或外部命令...`**
原因:安装时没勾 `Add python.exe to PATH`(见 2.2 节第 2 步)。
解法:重新运行安装包 → Modify → 勾选 `Add Python to environment variables`;完成后**必须关闭并重新打开终端**(PATH 是终端启动时读取的,旧终端不知道新配置)。

**报错 2:输入 `python` 后跳出 Microsoft Store(Windows 特有)。**
原因:Windows 内置了一个"假 python"快捷方式,劝你去商店下载。
解法:设置 → 应用 → 高级应用设置 → 应用执行别名 → 关闭 `python.exe` 和 `python3.exe` 两个开关。

**报错 3:`SyntaxError: invalid character '(' (U+FF08)`。**
原因:你用了**中文括号 ( )** 而不是英文括号 `( )`。Python 只认英文标点。`U+FF08` 就是中文左括号的编号。
解法:检查输入法状态,把代码里的中文括号、中文引号 `" "`、中文逗号 `,` 全部替换为英文的 `( ) " " ,`。**这是零基础学员第一周犯错率最高的问题,没有之一**。VS Code 里中文标点通常会显示得比英文标点"胖"一圈,肉眼可辨。

**报错 4:`SyntaxError: EOL while scanning string literal`。**
原因:字符串的引号没有成对——只写了左引号忘了右引号。EOL 意为 End Of Line(行结束),翻译成人话:"我读到行尾了,你的引号还没关上"。
解法:补上缺失的引号。

**报错 5:pip 安装库时 `Read timed out`。**
原因:没配镜像源,还在从国外服务器下载。
解法:回到 2.4 节执行镜像源配置命令。

> **读报错的通用三步法**(抄进笔记):
> ① 看**最后一行**——错误类型和描述在最后(`SyntaxError: ...`);
> ② 看**倒数第二段**的文件名和行号(`File "hello.py", line 3`)——它精确告诉你哪个文件第几行出的错;
> ③ 把最后一行**原样复制**去搜索引擎/AI 搜索——全世界的初学者踩过的坑都在网上留了答案。

# 下午 · 第一节(14:00 - 15:30):变量与数据类型

## 3.1 变量:给数据贴标签

上午的 `hello.py` 有个局限:内容是写死的。程序真正的威力在于处理**会变化的数据**——今天登录的用户叫张三,明天叫李四,程序代码不变,数据在变。承载"会变的数据"的机制,就是**变量**。

```python
# 变量的定义:名字 = 值
# 读法不是数学的"等于",而是"把右边的值,存进左边这个名字里"
name = "张三"        # 定义变量 name,存入字符串 "张三"
age = 28             # 定义变量 age,存入整数 28

print(name)          # 输出:张三 —— 注意 name 不带引号:我们要的是变量里存的值
print("name")        # 输出:name —— 带引号就是字符串本身,原样输出
print(age)           # 输出:28
```

**关于变量最准确的心智模型:标签,而不是盒子。** 很多教材把变量比作"盒子",但更准确的类比是**便利贴标签**:`name = "张三"` 是把写着 `name` 的标签贴到数据 `"张三"` 上。一个数据可以贴多张标签:

```python
a = "DeepSeek"       # 给字符串 "DeepSeek" 贴上标签 a
b = a                # 把标签 b 也贴到 a 指向的那个数据上(不是复制数据!)
print(b)             # 输出:DeepSeek —— 两张标签指向同一个数据
```

"标签"模型现在看起来和"盒子"模型没区别,但到 Day 04 学列表时,它能帮你避开一个价值两小时排错时间的大坑(两个变量指向同一个列表,改一个,"另一个也变了"),先埋个伏笔。

**变量命名规则(硬性,违反就报错):**

1. 只能由字母、数字、下划线组成;
2. 不能以数字开头(`1name` 非法,`name1` 合法);
3. 不能用 Python 关键字(`if`、`for`、`class` 等 35 个保留字,VS Code 会把它们显示成特殊颜色提醒你);
4. 区分大小写:`Name` 和 `name` 是两个不同的变量。

**变量命名规范(软性,违反不报错但会被同事鄙视):**

1. **见名知义**:`user_age` 远好于 `a`。三个月后回看代码的你,会感谢今天好好命名的你;
2. **蛇形命名法(snake_case)**:全小写 + 下划线分隔,如 `user_name`、`api_key`、`chat_history`——这是 Python 社区的官方风格(PEP 8 规范);
3. 常量(程序运行期间不变的值)全大写:`MAX_RETRY = 3`、`API_BASE_URL = "https://api.deepseek.com"`——Day 12 起我们会大量使用这种写法。

## 3.2 四种基本数据类型

Python 中的每个值都有"类型"。今天掌握四种基本类型,它们是以后一切复杂结构的原子:

```python
# ── 1. int(整数):没有小数点的数 ──────────────────────
age = 28                     # 年龄
max_tokens = 4096            # 【伏笔】大模型 API 的核心参数之一:限制回答最长多少 token(Day 16 详解)

# ── 2. float(浮点数):带小数点的数 ────────────────────
height = 175.5               # 身高
temperature = 0.7            # 【伏笔】大模型最重要的参数:温度,控制回答的随机程度(Day 16 详解)

# ── 3. str(字符串):被引号包裹的文本 ──────────────────
name = "张三"                 # 双引号
city = '上海'                 # 单引号,与双引号完全等价,但同一项目风格要统一(本课程统一用双引号)
prompt = "请用一句话介绍你自己"  # 【伏笔】发给大模型的指令就是一个字符串,字符串是 Prompt 工程的载体

# ── 4. bool(布尔值):只有 True / False 两个值,表示"真/假" ──
is_student = False           # 注意首字母必须大写:true 会报 NameError
stream = True                # 【伏笔】大模型 API 参数:是否流式输出/打字机效果(Day 24 实现)
```

用内置函数 `type()` 可以查看任何值的类型,遇到"这是什么类型"的疑惑就用它:

```python
print(type(28))         # <class 'int'>
print(type(175.5))      # <class 'float'>
print(type("张三"))      # <class 'str'>
print(type(True))       # <class 'bool'>
print(type("28"))       # <class 'str'> —— 注意!带引号的 28 是字符串,不是数字
```

最后一行是重点:**`28` 和 `"28"` 是完全不同的东西**。前者能做算术,后者只是两个字符排在一起。这个区别马上就会在实操里坑到你,我们提前演示:

```python
print(28 + 1)           # 29        —— 数字加法
print("28" + "1")       # 281       —— 字符串"加法"是拼接!
# print("28" + 1)       # TypeError —— 字符串和数字相加,直接报错
```

## 3.3 类型转换:四个"改造函数"

既然类型不同不能混用,就需要转换。四个转换函数,函数名就是目标类型名:

```python
# str() → 转成字符串
age = 28
text = "我今年" + str(age) + "岁"      # 数字转字符串后才能与字符串拼接
print(text)                            # 我今年28岁

# int() → 转成整数
age_str = "28"
age_num = int(age_str)                 # "28" → 28
print(age_num + 1)                     # 29

# float() → 转成浮点数
print(float("0.7"))                    # 0.7

# int() 转换失败会报错:ValueError —— 值不合法
# int("二十八")   → ValueError: invalid literal for int() with base 10: '二十八'
# int("28.5")    → 同样报错!字符串里带小数点不能直接转 int,要先 float("28.5") 再 int()
```

**为什么类型转换如此重要,重要到第一天就讲?** 因为下一节的 `input()` 函数**永远返回字符串**——用户输入 28,你拿到的是 `"28"`。想对它做任何数学运算,必须先 `int()`。今天下午的实操项目里,这个知识点会直接决定你的程序能不能跑通。

## 3.4 print 的进阶用法与 f-string(今天的重点技能)

`print` 还有几个实用姿势:

```python
# 一次输出多个值,用逗号分隔,输出时自动用空格连接
name = "张三"
age = 28
print("姓名:", name, "年龄:", age)      # 姓名: 张三 年龄: 28

# sep 参数:自定义分隔符   end 参数:自定义结尾(默认是换行)
print("2026", "07", "05", sep="-")      # 2026-07-05
print("加载中", end="")                  # 输出后不换行
print("...完成")                         # 加载中...完成
# 【伏笔】end="" 是 Day 24 实现"打字机效果"流式输出的关键参数:
# 大模型一个字一个字地吐,我们一个字一个字地打印且不换行,就是 ChatGPT 的效果
```

接下来是**今天下午最重要的知识点:f-string 格式化字符串**。前面拼接字符串用 `+`,又要转类型又要拼接,又丑又容易错。Python 提供了优雅得多的方案——在字符串前加一个 `f`,字符串里就可以用 `{}` 直接嵌入变量:

```python
name = "张三"
age = 28
height = 175.5

# 传统拼接(反面教材):繁琐、易错
intro_bad = "我叫" + name + ",今年" + str(age) + "岁,身高" + str(height) + "厘米"

# f-string(正面教材):直观、自动处理类型转换
intro_good = f"我叫{name},今年{age}岁,身高{height}厘米"
print(intro_good)                        # 我叫张三,今年28岁,身高175.5厘米

# {} 里不仅能放变量,还能放表达式(现场计算)
print(f"十年后我 {age + 10} 岁")          # 十年后我 38 岁

# 格式控制:{变量:格式说明}
pi = 3.1415926
print(f"保留两位小数:{pi:.2f}")          # 保留两位小数:3.14
price = 12345.678
print(f"千分位:{price:,.2f}")            # 千分位:12,345.68
ratio = 0.856
print(f"百分比:{ratio:.1%}")             # 百分比:85.6%
```

**为什么说 f-string 是"后续写 Prompt 模板的核心技能"?** 提前剧透 Day 17 的一行代码。所谓 Prompt 模板,就是一个留着空的指令,运行时把用户数据填进去:

```python
# Day 17 的 Prompt 模板长这样——本质就是今天学的 f-string:
user_question = "退货流程是什么?"
knowledge = "退货需在签收后 7 天内发起……"
prompt = f"""你是一名电商客服。请仅根据以下资料回答用户问题。
资料:{knowledge}
用户问题:{user_question}"""
```

看到了吗?**RAG 系统(Day 30)的"增强生成"环节,核心动作就是用 f-string 把检索到的资料塞进 Prompt**。今天把 f-string 练熟,就是在为 30 天后的企业级项目打地基。

三引号 `"""..."""` 也顺带出场了:它定义**多行字符串**,内容可以换行,写多行 Prompt 全靠它,请一并记住。

## 3.5 input:让程序听你说话

输出学完了,学输入。`input()` 函数让程序暂停,等用户敲键盘输入一行文字,回车后把输入内容**作为字符串**返回:

```python
# input 的括号里放"提示语",显示给用户看
name = input("请输入你的名字:")
print(f"你好,{name}!")

# ⚠️ 全天最重要的坑:input 的返回值永远是字符串
age = input("请输入你的年龄:")
print(type(age))                  # <class 'str'> —— 就算你输入 28,拿到的也是 "28"

# 想做数学运算,必须先转换类型
age = int(input("请输入你的年龄:"))     # 惯用写法:input 套在 int 里,一步到位
print(f"十年后你 {age + 10} 岁")
```

至此,你已经集齐了程序的三块基本积木:**输入(input)→ 处理(变量、运算、类型转换)→ 输出(print / f-string)**。所有软件——包括 ChatGPT——本质上都是这个三段式:ChatGPT 的 input 是你的问题,处理是模型推理,output 是回答。下午的实操,我们就用这三块积木搭出第一个完整的程序。


注意,这个流程图就是 3.5 节说的"输入 → 处理 → 输出"三段式。请把这个结构刻进脑子:Day 14 的 AI 助手,输入是用户消息、处理是调用大模型 API、输出是回答;Day 30 的 RAG 系统,输入是问题、处理是"检索 + 生成"、输出是带引用的答案。**结构不变,中间那块"处理"越来越强大,这就是我们 70 天的成长曲线。**

## 4.3 迭代式开发:从 v1 到 v4

企业里没有人一次性写完完美代码,都是"先跑起来,再变好"。我们把开发拆成四个版本,每个版本只解决一个问题——这种**小步迭代**的开发方式,请从第一天开始养成。

### v1:先让骨架跑起来(只做输入和原样输出)

新建文件 `day01/personal_card.py`:

```python
# =============================================
# 个人信息卡片生成器 v1
# 目标:先打通"输入 → 输出"的最小流程,不做任何加工
# 开发策略:先让程序跑起来,哪怕功能简陋——跑通的简陋程序
#          远远好于跑不通的完美程序
# =============================================

# ---- 输入环节:收集 5 项信息 ----
# input() 会暂停程序等待用户输入,返回值一律是字符串(str)
name = input("请输入你的姓名:")
age = input("请输入你的年龄:")
city = input("请输入你所在的城市:")
job = input("请输入你的期望岗位:")
hours = input("请输入你每天可投入的学习小时数:")

# ---- 输出环节:先原样打印,确认 5 个变量都正确拿到了 ----
print(name)
print(age)
print(city)
print(job)
print(hours)
```

运行 `python day01/personal_card.py`,依次输入五项信息,确认五行输出正确。**v1 的意义:验证主流程通畅。** 很多初学者一上来就写完整程序,报错了不知道错在哪;而 v1 只有输入输出,错了必然是这两处,排查范围极小。

### v2:加入计算(类型转换登场)

```python
# =============================================
# 个人信息卡片生成器 v2
# 新增:出生年份、总学习时长的计算
# 关键知识点:input 返回 str,算术运算前必须 int() 转换
# =============================================

name = input("请输入你的姓名:")

# 与 v1 的区别:input 外面套上 int(),拿到的直接就是整数
# 如果不转换,下面的 2026 - age 会抛出 TypeError:
#   unsupported operand type(s) for -: 'int' and 'str'
#   (人话:整数不能和字符串做减法)
age = int(input("请输入你的年龄:"))
city = input("请输入你所在的城市:")
job = input("请输入你的期望岗位:")
hours = int(input("请输入你每天可投入的学习小时数:"))

# ---- 处理环节:两个计算 ----
birth_year = 2026 - age       # 出生年份:今年是 2026 年
total_hours = hours * 70      # 70 天课程的总学习时长

# ---- 输出环节:用 f-string 组装人话 ----
print(f"姓名:{name}")
print(f"年龄:{age} 岁(约 {birth_year} 年出生)")
print(f"城市:{city}")
print(f"期望岗位:{job}")
print(f"学习计划:每天 {hours} 小时 × 70 天 = 共 {total_hours} 小时")
```

运行测试。故意做一个**破坏性实验**:年龄输入"二十八",观察报错:

```
ValueError: invalid literal for int() with base 10: '二十八'
```

用上午学的"读报错三步法"分析:最后一行说 `ValueError`(值错误)——`int()` 收到了一个没法转成整数的值 `'二十八'`。程序崩溃了,怎么办?**今天先不处理**,因为优雅地处理它需要 Day 03 的条件判断和 Day 10 的异常捕获。请把这个不爽记下来——它就是你后天学 if 判断、下周学 try/except 的动力。好课程的知识点不是"排出来的",是"被问题逼出来的"。

# 晚自习(19:00 - 21:00):Git 与 GitHub —— 让你的每一行代码都被看见

## 5.1 为什么第一天就学 Git?

Git 是**版本控制工具**,GitHub 是**代码托管网站**。对你来说,今天配置它们有三个现实理由:

1. **求职硬通货**:面试官看到"70 天每天都有提交记录"的 GitHub 主页,比简历上任何形容词都有说服力;
2. **代码保险箱**:电脑坏了、误删了,云端始终有备份;
3. **行业通用语**:未来工作中,代码协作 100% 基于 Git,早一天熟悉早一天受益。

两者的关系一句话讲清:**Git 是安装在你电脑上的记账软件,GitHub 是云端的账本存放处。** 你在本地用 Git 记账(每天写了什么代码),再把账本推送(push)到 GitHub 保存和展示。

## 5.2 安装与配置 Git

**安装**:访问 `https://git-scm.com/downloads` 下载对应系统安装包。Windows 一路默认下一步即可(选项很多,全部保持默认);macOS 终端输入 `git --version`,若未安装系统会自动弹出安装引导。

**验证**:终端输入 `git --version`,输出 `git version 2.x.x` 即成功。

**自报家门**(Git 要求每笔"账"都有记账人签名,只需配置一次):

```bash
git config --global user.name "你的英文名或拼音"
git config --global user.email "你的邮箱"
```

注意:这里的名字邮箱只是签名,和 GitHub 账号**不要求一致**,但建议填 GitHub 注册邮箱,这样 GitHub 能把提交记录关联到你的头像。

## 5.3 注册 GitHub 并创建课程仓库

1. 访问 `https://github.com/` 注册账号。用户名慎重取——它会出现在你的简历上(如 `github.com/zhangsan-dev`),建议用"名字拼音 + dev/ai"的组合,不要用 `woaichigua666` 这种;
2. 注册后点击右上角 `+` → `New repository`;
3. 仓库名填 `llm-course-70days`,描述填 `我的 70 天大模型应用开发学习记录`,选 **Public**(公开,给面试官看的),勾选 `Add a README file`,点击 `Create repository`。

## 5.4 Git 最小工作流:今天只学四个命令

Git 有上百个命令,今天只学最小闭环的四个。先理解模型:

```
   工作区            暂存区              本地仓库             GitHub
(你写代码的地方)  (打包台:待提交清单)  (你电脑里的账本)      (云端账本)
      │                │                  │                  │
      │── git add ────▶│                  │                  │
      │   (放上打包台)   │── git commit ──▶│                  │
      │                │   (盖章记账)      │─── git push ────▶│
      │                │                  │   (推送上云)       │
```

**第 1 步:把 GitHub 仓库克隆(下载)到本地。** 在 GitHub 仓库页面点绿色 `Code` 按钮,复制 HTTPS 地址,然后在终端:

```bash
# cd 命令:切换到你想存放代码的目录(以 D 盘为例;macOS 如 cd ~/)
cd D:\
# clone:把云端仓库完整复制到本地,会生成 llm-course-70days 文件夹
git clone https://github.com/你的用户名/llm-course-70days.git
```

> 从今天起,课程代码就写在这个 `llm-course-70days` 文件夹里(代替 2.5 节临时创建的 llm-course)。用 VS Code 打开它,把今天的 `hello.py` 和 `personal_card.py` 移进 `day01` 子文件夹。

**第 2 - 4 步:提交今天的代码。** 在 VS Code 集成终端(确认当前目录是仓库根目录):

```bash
# ① 查看状态:哪些文件是新增/修改的(红色 = 未加入暂存区)
git status

# ② 把 day01 文件夹下所有文件放上"打包台"
git add day01/

# ③ 盖章记账:-m 后面是"提交信息",描述这次改动做了什么
#    提交信息规范:动词开头、说人话、说清楚做了什么
git commit -m "Day01: 完成开发环境搭建与个人信息卡片程序"

# ④ 推送到 GitHub(第一次推送会弹出浏览器让你登录授权,按提示操作)
git push
```

推送成功后,刷新 GitHub 仓库页面——你的代码已经在云端了,主页的贡献日历上出现了第一个绿格子。**未来 69 天,你的任务之一就是让这个日历连成一片绿色。** 每天代码写完,`add → commit → push` 三连,两分钟的事,从今晚开始。

> 常见问题:`git push` 报 `Authentication failed`。GitHub 从 2021 年起不再支持密码推送,如果浏览器授权流程没走通,需要创建 Personal Access Token:GitHub → Settings → Developer settings → Personal access tokens → Generate new token(勾选 repo 权限),推送时用 token 代替密码。详细图文步骤见本目录 `code/git_setup_guide.md`。

# 【课堂笔记】Day 01 知识点速查表

**环境三件套**

**四种基本类型**
| 类型 | 例子 | 大模型场景 |
|------|------|-----------|
| int | `28`、`4096` | max_tokens 参数 |
| float | `0.7` | temperature 参数 |

| bool | `True` | stream 流式开关 |

**变量命名**
- 硬规则:字母数字下划线、不能数字开头、不能用关键字、大小写敏感
- 软规范:snake_case 蛇形命名;常量全大写(`MAX_RETRY = 3`)

**Git 四连**
`git status` 看状态 → `git add 路径` 上打包台 → `git commit -m "信息"` 盖章 → `git push` 上云

**读报错三步法**
① 看最后一行(错误类型) ② 看文件名+行号 ③ 原样复制去搜索

**今日高频错误**
- 中文标点(全角括号/引号/逗号)→ SyntaxError
- input 结果直接做算术 → TypeError
- `int("二十八")` / `int("28.5")` → ValueError
- 没勾 PATH → 'python' 不是内部或外部命令

# 【附录】课堂答疑实录(晚自习整理)

> 以下是当天课堂与晚自习答疑中最有代表性的九个问题,由助教整理。你现在冒出来的疑问,大概率也在里面。

**问 1:为什么选 Python,不选 Java 或 C++?我听说 C++ 更快。**

答:三个原因。第一,生态:大模型领域几乎所有的官方 SDK、开发框架(LangChain、LlamaIndex)、训练工具(PyTorch、LLaMA-Factory)都把 Python 作为第一公民,用别的语言等于逆着生态走。第二,开发效率:同样的功能,Python 的代码量通常只有 Java 的三分之一到一半,对以"快速交付应用"为目标的我们,开发效率远比运行速度重要。第三,速度问题其实不存在:大模型应用 99% 的时间花在"等大模型 API 返回结果"上(网络 I/O),你的代码跑多快根本不是瓶颈——就像点外卖,骑手在路上要 30 分钟,你把"拨电话"的速度从 3 秒优化到 0.3 秒毫无意义。

**问 2:我可以用 PyCharm 吗?同事说 PyCharm 更专业。**

答:可以,PyCharm 是优秀的 Python IDE。但课程统一用 VS Code,理由是:免费、轻量、插件生态覆盖我们全部技术栈(Python、Jupyter、Docker、前端),而且它是目前 AI 编程助手集成最好的编辑器。统一工具还有个现实好处——你报错时讲师能秒懂你的界面。学完课程后想换 PyCharm,半天就能上手,编辑器不是核心竞争力。

**问 3:交互模式(>>>)和写 .py 文件运行,什么时候用哪个?**

答:交互模式适合"快速验证一个小疑问",比如忘了 `int("28.5")` 会不会报错,进去敲一下 10 秒出答案,用完即走。正式代码一律写文件:文件能保存、能修改、能提交 Git、能被别人运行。一个实用建议:以后学新函数时,先在交互模式里把玩两分钟,再写进文件——这个"先玩再用"的习惯能省大量调试时间。

**问 4:注释是给谁看的?我自己写的代码我自己记得。**

答:三个月后的你 = 陌生人。这是全行业公认的事实:工程师读代码的时间是写代码的十倍,而"当时怎么想的"是最容易蒸发的信息。另外注释还有一个新时代的用途:以后你用 AI 辅助编程时,注释写得清楚的代码,AI 帮你改起来准确率明显更高——注释同时是给人和 AI 看的说明书。但注意方向:注释写"为什么",不写"是什么"。`age = age + 1  # 年龄加一` 是废话注释;`age = age + 1  # 按周岁计算,过了生日才加` 才有信息量。

**问 5:为什么变量名要用英文?我写 `名字 = "张三"` 好像也能跑?**

答:确实能跑,Python 3 支持中文变量名。但强烈不建议:① 中英文切换输入法会拖慢速度还容易混入全角标点(今天的头号报错);② 行业代码全是英文命名,你看开源项目、和同事协作都得适应英文;③ 部分老旧系统和工具对非 ASCII 字符支持不佳。英文水平不用焦虑,编程常用词汇就几百个,而且都是 name、age、user、message 这种初中词汇,写两周就熟了。

**问 6:f-string 的 f 是什么的缩写?为什么非要加它?**

答:f 是 format(格式化)的缩写。不加 f,字符串里的 `{name}` 就只是七个普通字符,Python 不会做任何处理,原样输出 `{name}`。加了 f,等于告诉 Python:"这个字符串里的大括号是占位符,请把变量的值填进去"。今天很多同学卡片输出了一堆 `{name}{age}`,回去检查一下,八成是漏了 f。

**问 7:我的电脑是 8G 内存的老笔记本,能跟完 70 天吗?**

答:前 50 天完全没问题——我们调用的大模型都在云端,你的电脑只负责发请求收结果,写代码本身对配置要求极低(VS Code + Python 占用不到 2G)。Day 51 - 55 微调阶段需要 GPU,但方案是**租云端 GPU**(AutoDL,约 2 - 5 元/小时,一周实验总花费几十元),不需要你买显卡。唯一建议:内存低于 8G 的同学,上课时少开浏览器标签页。

**问 8:今天讲的"输入 → 处理 → 输出"三段式,和大模型有什么关系?我感觉今天学的东西和 AI 没关系。**

答:关系是"同构"。今天的程序:input 收用户文字 → 计算 → print 输出。Day 14 的 AI 助手:input 收用户问题 → **把问题发给大模型 API,拿回答案** → print 输出。结构一模一样,只是"处理"那一格从"减法"换成了"调用大模型"。这门课的设计就是不断加厚中间这一格:Day 12 换成 API 调用,Day 30 换成"检索知识库 + 生成",Day 41 换成"Agent 自主决策循环"。所以今天不是"和 AI 没关系的一天",而是你拿到了那个最终会装上大模型引擎的车架。

**问 9:GitHub 打不开或者很慢,怎么办?**

答:分情况。① 网页偶尔慢:换个时间段,或刷新几次,GitHub 在国内可以访问但不稳定;② `git clone` / `git push` 超时:优先用 HTTPS 协议(我们课上用的就是),不行就多重试几次;③ 长期不稳定的同学可以用国内镜像站 Gitee(码云)做"双备份":GitHub 为主(面试官看的是它),Gitee 为辅,Git 支持一个仓库推送到多个远端,具体配置方法在 `code/git_setup_guide.md` 基础上加一条 `git remote add gitee 地址` 即可,有需要的晚自习找助教。注意:不要因为网络问题就放弃每日提交,绿格子日历断一天,习惯就容易断一片。
